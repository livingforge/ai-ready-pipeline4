# arp4-repair ― パース結果の切れ目を直す

**あなたが直すのは `parsed/` の Markdown だけである。** 整理結果（`organized/`）も
正本（`spec/`）もここでは触らない ―― 直すのは「資料がどう書かれていたか」の写しで
あって、「我々がどう決めたか」ではない。整理結果を書くのは
[arp4 スキル](../arp4/SKILL.md) の持ち場である。

## なぜ直すことがあるのか

塊の区切りは**意味の判断ではなく提示上の都合**である。区切りを間違えても値は 1 つも
落ちず、番地は全部付いているので読み直せる ―― そう決めてあるので、機械は割ったこと
を長いあいだ黙っていた。

黙って割れているのが困るのは、**読むのが人ではなく整理層だから**である。3 つに割れた
表は 3 つの表として読まれ、`項番 21` から先に列があることに誰も気づかない。ここは
その取りこぼしを、**原本を開いて**塞ぐための持ち場である。

## 打ってはいけない場面

- **凍結済みのラウンド**（`organized/.frozen.yml` がある）では直さない。凍結したレコード
  の足元が黙って動く ―― 新しいラウンドを起こす（→ [arp4/docs/freeze.md](../arp4/docs/freeze.md)）。
- **原本が手元に無い**とき（`arp4 suspect` が指す資料を開けない）は直さない。開かずに
  統合するのは、機械の当て推量を人の判断の顔で書くことである。

## ① 疑いを機械に出させる

```bash
arp4 suspect --root <プロジェクト根>
# --round <名前>   そのラウンドだけを見る（既定: いちばん新しいもの）
# --path <部分パス> 分担しているとき。見た本数が一緒に出るので、絞り間違えは数で分かる
```

`exit 0` なら疑いなし、`exit 3` はあなたの手番である。**`error` は 1 つも出ない** ――
1 つの表か 2 つの表かは資料を開かないと決まらないので、機械が「誤り」と名乗れば
その名乗りのほうが嘘になる。

| コード | 機械が見たもの | 直し方 |
| --- | --- | --- |
| `S001` | 行の範囲が 1 行も違わない塊が横に並び、**幅 1 列のものが混じる** | **撮り直す**（→ ②） |
| `S002` | 列の範囲が同じ塊が縦に並び、**見出しの行が繰り返されている** | 原本を開いて判断（→ ③） |
| `S003` | 行の範囲が 1 行も違わない塊が横に並んでいる | 原本を開いて判断（→ ③） |

## ② `S001` は撮り直す ― 手を入れていても捨てない

`S001` は**古い arp4 が自分で作った隙間**である（方眼紙の設計書は論理列 1 本を数列ぶん
横結合して作るので、値が結合の左上にしかなく、隣の列までの距離が結合の幅になる）。
資料の側に隙間は無いので、**いまの arp4 で撮り直すだけで 1 つの表に戻る。**

手を入れたパース結果がある場合は、次のどちらかで選ぶ。

**端末で打てるなら** ―― `arp4 parse` が 1 本ずつ聞いてくる。

```bash
arp4 parse --root <根> <資料のパス>
# 「… は編集されています。上書きしますか？ [y/N/a(すべて)]」
#   手で直した写し → N ／ それ以外 → y
```

**端末が無いなら**（エージェント・CI では 1 度も聞かずに全部守る）―― 書かせてから
git で戻す。**パース結果をコミットしてから**打つこと。

```bash
git add -A .arp && git commit -m "パース結果の手入れ"
arp4 parse --root <根> <資料のパス> --yes
git checkout HEAD -- <手を入れた写しのパス>...
git diff --stat        # 直ったぶんだけが残っているか見る
```

撮り直すと `sources.yml` に **arp4 が書いた版の指紋**が入るので、次からは手を入れた
写しだけが正確に守られる（`編集の有無を確かめられないため` が `編集済みのため` に
変わる）。

## ③ `S002` / `S003` は原本を開いて判断する

**撮り直しでは変わらない。** 資料の側に空行・空列があり、機械にはそこが切れ目に
見えている ―― 1 つの表なのかどうかは、資料を読んだ人にしか言えない。

### 見るもの

1. **原本**（Excel / Word / PDF）を開く。これが第一である。
2. 開けないとき、または図形で描かれていて機械が読めていないときは、絵にする。
   ```bash
   arp4 render --root <根> <資料のパス>      # 図形のシートを絵にする
   ```
3. 貼り付け画像は既に `images/` に出ている（塊 `i1`）。Windows OCR の読みは塊 `o1`
   にある ―― **`o1` は機械の読みであって資料の字ではない。** 値として使う前に必ず
   絵を開いて確かめる。

### 1 つの表だと言える印

- **項番が通っている**（前の塊が `1〜20`、次が `21〜40`）。
- 繰り返された見出しの行が**一字一句同じ**である。
- 印刷設定の塊（`p1`）に**印刷タイトル行・印刷タイトル列**が指定されている ――
  「ここまでが見出し」と資料の作成者が決めた申告で、ページをまたぐ表の強い証拠になる。
- 左右なら、右の塊の 1 列目が左のキー列（項番・ID）を**繰り返している**。

### 2 つの表だと言える印

- 表題の行が違う（前が「入力項目」、後ろが「表示項目」）。
- 列の意味が続いていない（見出しの語は同じでも、値の並びが別の対象を指している）。
- 項番がどちらも `1` から始まる。

**決められないときは直さない。** そのまま残して、整理層に判断を渡すほうがよい ――
間違って統合すると、資料が言っていない並びを作ることになる。

## 統合するときに守ること

- **値を作らない。** 統合は塊の付け替えであって、書き換えではない。空欄は空欄のまま、
  和暦も表記ゆれもそのまま残す。原本に無い字は 1 つも書かない。
- **番地を残す。** 統合した塊の `at` は**覆う範囲**へ広げる（`B1:E22` と `B25:E46` を
  1 つにするなら `at=B1:E70`）。列がずれるなら**空の列を残す** ―― 番地から表の中の
  位置を割り出せることが、区切りを許している前提である。
- **繰り返された見出しの行は残す。** 落としてもよいが、落としたら塊の上の `>` の行に
  「見出しの繰り返しを 2 行落とした」と書く。**黙って落とすのがいちばん悪い。**
- **申告（`>` の行）は消さない。** 「機械が読めなかった」という事実は、統合しても
  消えない。
- ファイル先頭の `# タイトル` と `<!-- source: ... -->` は触らない。
- **アンカーの形は変えない**（`s1-t1` の `s1` はシートが何枚目かである）。統合先は
  残るほうのアンカーをそのまま使う。

## アンカーを消す前に

要らなくなった塊は削除してよい。**ただし、指しているものが無いかを先に確かめる。**

```bash
grep -rn "s1-x2" .arp/rounds/<ラウンド>/organized/
```

当たったら、**先に整理結果の出典を統合先のアンカーへ付け替える**。付け替えずに消すと
`arp4 lint` / `arp4 freeze` が `G004`（アンカーが実在しない）で止める ―― 止まるのは
正しい動きだが、あとから直すほうが手間が多い。

## 直したあと

```bash
arp4 suspect --root <根>          # 疑いが減った・消えたことを機械に言わせる
arp4 lint --root <根> <整理結果>   # アンカーを消したなら G004 が出ないことを見る
git add -A .arp && git commit -m "パース結果の切れ目を直した"
```

**必ずコミットする。** 機械が出したものと人が直したものの区別は、git にしか無い。

直した写しは、次の `arp4 parse` から**編集済みとして守られる**（`sources.yml` に
記録された版と中身が食い違うため）。守られたことは `編集済みのため上書きしませんでした`
として必ず出る ―― 黙って消えることはない。

## やってはいけないこと

- 原本を開かずに統合する。
- 値を書き換える・空欄を埋める・単位や日付を直す（それは整理層の仕事ですらない ――
  正本側の決定である）。
- 塊を**分割**する。`suspect` は「割れているかもしれない」としか言わない。
- ここで `organized/` を直す（→ [arp4 スキル](../arp4/SKILL.md)）。
- 凍結済みのラウンドで直す。

## arp4 が打てないとき

導入・起動コマンド・端末の符号化は [arp4-setup](../arp4-setup/SKILL.md) が持っている。
