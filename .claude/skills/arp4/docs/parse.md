# ① parse ― 既存資産をパース結果にする

```bash
arp4 parse --root "$R" "$R"/src "$R"/ddl     # 作業中のラウンドの続きに入る
arp4 parse --root "$R" "$R"/src --new-round  # 資料が更新されたので新しいラウンドを起こす
arp4 parse --root "$R" "$R"/src --round r003 # ラウンドを指定する
```

| 拡張子 | 取るもの | 1 本の単位 |
| --- | --- | --- |
| `.xlsx` `.xlsm` | セルの面・図形・申告事項（`.xlsm` は**マクロの有無を `P006` で言うだけ**で、中身は取らない。下記） | シート 1 枚 |
| `.pptx` `.pptm` | 図形・接続・表（`a:tbl`）・発表者ノート・コメント | スライド 1 枚 |
| `.docx` `.docm` | 段落・表・コメント・**未確定の変更履歴**・脚注・ヘッダとフッタ | 見出し 1 の節 |
| `.pdf` | ページごとの本文（**表は組み直さない**）。テキスト層の無いページは絵にして OCR | しおりの節 |
| `.csv` `.tsv` | 表 1 枚（**当てた区切りと文字コードを必ず申告する**） | 1 ファイル |
| `.py` | クラス・メソッド・シグネチャ・取り込み・テスト | 1 ファイル |
| `.java` | 型・メンバ・注釈・取り込み（宣言の頭だけ。本体は読まない） | 1 ファイル |
| `.sql` `.ddl` | `CREATE TABLE` / `CREATE INDEX` / `COMMENT ON`（残りは数えて申告） | 1 ファイル |
| `.md` `.txt` | 見出しごとに 1 塊。本文は原文のまま | 1 ファイル |

読めない形式は `P001` で数えて報告する（報告せずに飛ばすことはない）
→ [troubleshooting.md](troubleshooting.md)。**貼り付け画像の中の文字は読む**
（Windows OCR。下記 `o1`）。

出力は `.arp/rounds/<ラウンド>/parsed/` で、元のフォルダ構造をそのまま写す。
**1 冊が何本にも割れる形式は、原本の名前がディレクトリになる。**

```
<リポジトリ>/資料/A/基本設計書.xlsx
  → <リポジトリ>/.arp/rounds/r001/parsed/資料/A/基本設計書.xlsx/受注テーブル.md
<リポジトリ>/資料/A/方式提案.pptx
  → <リポジトリ>/.arp/rounds/r001/parsed/資料/A/方式提案.pptx/01_全体構成.md
```

**割る構造が資料に無ければ 1 本のまま出る** ―― 見出しスタイルを使っていない Word、
しおりの無い PDF がそれである。段落数やページ数で割ることはしない（**資料に無い
切れ目を機械が作る**ことになる）。

## アンカーの種類

シート 1 枚の中は、取り出し元が違うものを別のアンカーに分けて出す。片方だけを出典に
したいことがあるからである。`s3-t1` の `3` はシートの並び順（1 始まり）を表す。

**接頭辞は形式で変わるが、種別の意味は変わらない。**

| 接頭辞 | 何番か | 形式 |
| --- | --- | --- |
| `s3-` | シート／スライドの並び順 | `.xlsx` `.xlsm` `.pptx` `.pptm` |
| `w3-` | 節（見出し 1）の並び順 | `.docx` `.docm` |
| `p3-` | **ページ番号** | `.pdf` |
| （無し） | 割れないので番号を持たない | `.csv` `.tsv` `.md` `.txt` |

| アンカー | 中身 | 見落としやすい理由 |
| --- | --- | --- |
| `s3-t1` | 表（セルの塊） | ― |
| `s3-x1` | 表にならなかったセル（番地付きの箇条書き） | ― |
| `s3-f1` | 計算結果が保存されていない数式の番地 | 表の上では空欄に見える |
| `s3-e1` | エラー値（`#REF!` `#N/A`）の番地 | 表の上では値に見える |
| `s3-d1` | 取り消し線の掛かったセルの番地 | 画面では消してあるのに、表では生きた行と同じに見える |
| `s3-m1` | セルのコメント（メモ・スレッドコメント） | 表に出てこない（セルの上に浮いている） |
| `s3-l1` | リンクの行き先 | 表にあるのは表示文字列だけ |
| `s3-g1` | 図形・SmartArt の中の文字 | セルではないので表に出ない |
| `s3-c1` | 図形の接続（`元 / 向き / 先` と線の見た目） | 同上 |
| `s3-k1` | グラフのタイトル・系列・参照範囲 | 値は別のシートにある（`k1` はそこへの案内） |
| `s3-a1` | 代替テキスト（図形・群・画像・図表） | 中身は取れないが、何が描いてあるかは人が書いている |
| `s3-i1` | ブックから取り出した画像のファイル名とリンク | 機械は絵を読まないが、エージェントは開いて読める |
| `s3-o1` | その画像から Windows OCR が読んだ文字 | **読み違えが混ざる**（機械の読みであって資料の字ではない） |
| `s3-p1` | 印刷したときだけ見えるもの（ヘッダ・フッタ・繰り返す見出しの行と列） | 紙では全ページに刷られているのに、セルには 1 つも書かれていない |

Excel 以外にしか出ないものが 3 つある。

| アンカー | 中身 | 見落としやすい理由 |
| --- | --- | --- |
| `s3-n1` | **発表者ノート**（`.pptx`） | スライドの箱は結論だけを載せるので、**そう決めた理由がここにしか無い**ことがある |
| `w3-h1` | 段落の本文（`.docx`。原文のまま） | ― |
| `w3-f1` | **脚注**（`.docx`） | 但し書き（例外条件）はここに置かれる。本文の流れには出てこない |

読み替えるものも 3 つある ―― 意味は同じで、指しているものが形式で変わる。

| アンカー | Excel では | 新しい形式では |
| --- | --- | --- |
| `w3-d1` | 取り消し線の掛かったセル | **変更履歴で消された文字**（`.docx`。まだ確定していない） |
| `w3-p1` | 印刷したときだけ見えるもの | ヘッダとフッタ（`.docx`。**文書全体に掛かる**ので別の 1 本に出る） |
| `p3-i1` / `p3-o1` | 貼り付け画像とその OCR | **テキスト層の無いページを焼いた絵**（`.pdf`）とその OCR |

**アンカーは行単位ではなく塊単位である。**表 1 枚から 10 レコード起こしても、全部が同じ
`s1-t1` を指すのが正しい。

## 形式ごとに気をつけること

**PowerPoint。** 非表示のスライドは読まない（`P003` で言う）。レイアウトとマスターに
書かれた文字（ページ番号・フッタ・定型の見出し）は**取っていない** ―― 文書番号・版・
機密区分がそこにしかないことがある。

**Word。** 見出し 1 で節に割る。**変更履歴が確定していない資料は普通に回ってくる**
（`P019`）―― 本文は**変更を反映した姿**で出し、消された文字は `d1` に出す。どちらが
現行の仕様かは機械が決めない。

**PDF。** **表は組み直さない。** PDF が持っているのは位置を持った文字だけで、列の
切れ目はどこにも書かれていない ―― 行のまま出る。テキスト層の無いページ（紙をスキャン
したもの）は `P017` で言い、絵にして `i1` へ、中の字は OCR で `o1` へ出す。

**CSV。** 区切りと文字コードは**機械が当てている**ので、決めた結果をパース結果の頭に
必ず書く（`文字コードは cp932、区切りは カンマ として読みました（120 行のうち 100% が
7 列）`）。**決められなければ表にしない**（`P018` ―― 原文のまま出る）。値そのもの
（桁・コード値）を使う前に、1 行だけでも原本と読み比べること。

## ラウンドは日付で切らない

名前は連番（`r001`）で、既定の宛先はまだ凍結していない最も新しいラウンドである。
ラウンドは「いつ作業したか」ではなく「どの資料の版を扱っているか」の単位である。

| したいこと | オプション |
| --- | --- |
| 昨日の続き（同じ資料） | なし |
| 資料そのものが更新された | `--new-round` |
| 過去のラウンドを名指しする | `--round r002` |

**取り込んだ版は `sources.yml` に指紋として残る。**資料が差し替わってもパース結果は
古いまま残り、アンカーは全部実在するので検査は通ってしまう。指紋があるので、`freeze` と
`check` が `G019` で指摘する。上の表の 2 行目を選ぶかどうかは、これを見て決める。

## 図形はテキストと接続を取る

業務フロー・ER 図・状態遷移図・画面レイアウトは図形で描かれていることが多い。箱の中の
文字は `s4-g1` に、線がどの図形とどの図形を結んでいるかは `s4-c1` に出る。

```markdown
## 図形（テキスト）  <!-- a:s4-g1 at=図形 19 個 -->

- `図形1` オーダー入力<br>（代行入力）
- `図形2` 与信の枠内？

## 図形の接続  <!-- a:s4-c1 at=接続 9 本 -->

| 元 | 向き | 先 | 名前 | 線種 |
|---|---|---|---|---|
| オーダー入力<br>（代行入力） | → | 与信の枠内？ | 委託 | 破線 |
| 与信の枠内？ | → | 出荷指示 | コネクタ 12 | 実線 |
```

**接続は転記であって推測ではない。**接続子は繋がっている図形の id と矢羽根を明示的に
持っているので、`c1` は資料に書いてあるものをそのまま写している。矢羽根の無い線は `―`
（無向）のまま出るので、どちらが先かを決めつけない。

**`元 / 向き / 先` の右に線の見た目が付く。**体制図・業務フローの凡例は「実線＝指揮命令 /
破線＝委託」のように**線種で意味を描き分ける**ので、線 1 本ずつの意味はここでしか決まらない。

| 列 | 出るとき |
| --- | --- |
| `名前` | 接続子に名前が 1 つでも付いていれば |
| `線種` | 線種が 1 つでも読めれば（`実線` `破線` `点線` `一点鎖線`…） |
| `線色` `太さ` | 行のあいだで**違うときだけ**（全部同じなら描き分けていない） |

**線種が全部 `実線` なのも答えである。**凡例が破線での描き分けを謳っていても図に破線が
1 本も無いなら、資料の側に情報が無い。列が空欄なのは線種がテーマ側にあって解決していない
ときで、そのときは**「実線」と決めつけずに空で出る。**

**`名前` は鵜呑みにしない。**Excel は線に `コネクタ 12` `直線矢印コネクタ 3` のような名前を
**自動で振る**。人が付けた `委託` `点検依頼` と同じ列に並ぶが、機械はどちらかを判定せず
**そのまま転記する**（判定すると落とした判断が見えなくなり、資料の言語が変われば人の付けた
名前まで捨てる）。捨てるのは読んだ側の仕事である。線には代替テキストもテキスト枠も無いので、
**線に付いた言葉の唯一の在り処が名前**になることがある。

箱の中の改行と行頭の字下げは残る（`機能構成<br>　1. 受注管理<br>　　1-1. 受注登録`）。
機能構成図を 1 つのテキストボックスで書くのは日本の設計書ではごく普通で、そこでは
親子関係が段落頭の全角空白にしか現れない。

`テキストも接続も取れていません` と出ているシートは、資料に情報が無いのではなく、機械が
読めていない。「図形がありません」も「図がありません」という意味ではない。近年の体制図・
業務フローは SmartArt で描かれていることが多く、図形の数え方では 0 個になる。

`g1` と `c1` からレコードを起こすか `未読取` を宣言するかの判断 → [organize.md](organize.md)。
グラフのあるシートは `k1` も出る（下記「表に出てこないもの」）。

### 取れないもの

| 取れないもの | どうするか |
| --- | --- |
| 配置（枠で括られたゾーン・段組み・注記の位置） | `arp4 render` で絵にする |
| どこにも繋がっていない線（線を目分量で置いた図） | 本数を申告する。絵にしても決まらない |
| 相手が文字を持たない線（ゾーンの囲み枠へ落ちる線） | 本数を申告する。絵にすれば向かう先は読める |
| 貼り付け画像の絵（図・写真・レイアウト） | 実体を `images/` へ出す（`i1`）。撮り直しても絵は絵のままなので、開いて見るのはあなたである（中の**文字**は `o1` に出ている） |
| SmartArt の箱どうしの繋がり | 箱の文字は `g1` に出る。順序が要るなら絵にする |
| グラフに描かれている数 | どのシートのどの範囲かは `k1` に出る。そのシートのパース結果を読む |
| 埋め込みオブジェクト（Word・PDF の貼り込み） | 代替テキストが `a1` に出ることがある。**元ファイルを `arp4 parse` に渡せばそれ自体は読める** |

**取れない線は 2 種類あり、次にやることが正反対である。**片方は絵にすれば読め、片方は
絵にしても決まらない。申告文がどちらかを言い分ける。

### 画像は実体ごと出る（`i1`）。中の文字も読んである（`o1`）

**「機械が読めない」と「誰にも読まれない」は別である。**貼り付け画像に描かれた業務フロー・
現行画面のハードコピーは `images/` に実体で出るので、開けば読める。出典には
`s<番号>-i1` を指す。

**文字は機械（Windows OCR）が読んで `s<番号>-o1` に出してある。**貼ってある画像の多くは
表・画面・帳票を撮ったもので、そこにあるのは絵ではなく字である。

- **平坦で文字しか無い画像なら、`o1` だけで足りる**（画像を開く必要は無い）
- **図・写真・レイアウトが要るなら画像を開く**（`o1` は「文字は見つかりませんでした」になる）
- **`o1` を出典にするときは `s<番号>-o1` を指す**（`i1` ではない。出自が違う）

**`o1` は資料の字ではなく機械の読みである。**`ORDER-001` が `ORDER-OOI` に、`ロゴ` が
`T 鋤 Lロら工 TEC` になる。**値そのもの**（桁数・コード値・型）を `o1` から起こすときは、
画像を開いて確かめること。読み違えたまま整理結果に書くと、以降のラウンドでは
それが正本の値になる。

`o1` に「読みにいっていません」「読めませんでした」と書いてあることもある（`--no-ocr`、
Windows でない、言語パックが無い、絵として開けない画像）。**空でないのは意図的である** ――
空の `o1` は「画像に文字が無かった」と読めてしまう。

**`o1` も他のアンカーと同じく整理の対象である**（`freeze` の未整理 0 に数える）。字が
出ていない `o1` は、その画像の `i1` と同じ理由で `out_of_scope` に落とす（`reason` は
「画像は絵で、文字は無い」など。読めていないだけなら `kind: 未読取`）。

実体を取り出せない画像もある。リンク画像はブックの中に実体を持たないので、元の画像
ファイルを当たるか、`out_of_scope` に `kind: 未読取` で宣言する。

## `arp4 render` ― 読めなかった範囲を絵にする

```bash
arp4 render --root "$R" "$R"/資料                      # 図形のあるシートだけ撮る（既定）
arp4 render --root "$R" "$R"/資料 --sheet 業務フロー     # シートを名指しする
arp4 render --root "$R" "$R"/資料 --sheet 業務フロー --range AB5:BH25   # 範囲を狭める
arp4 render --root "$R" "$R"/資料 --pending            # `未読取` と宣言したシートだけ
```

**ただし `c1` を先に読むこと。**接続表が出ているなら、絵を見るより正確で速い。縮小された
図では矢印の始点・終点を取り違えることがあるので、**両者が食い違ったら `c1` を採る。**

**`render` には `parse` と同じパスを渡す。**貼り先は渡したパスの共通の親から決まるので、
`parse` に `資料/` を渡して `render` に 1 冊だけ渡すと、絵は撮れているのに貼り先が 1 つも
見つからない（終了コードは 0 なので成功に見える）。`--pending` でも同じ理由で資料のパスが要る。

撮った絵は図形のアンカーへ貼り戻される。`s4-g1` の直下の
`![…](../../images/…png)` を Read で開けば、線の接続も矢印の向きも読める。読んで確定
できたなら、出典は `s4-g1` のままレコードにしてよい（絵は本文の一部であって、別の出典では
ない）。

- 長いシートは複数枚に割れる（`-1.png` `-2.png`）。ただし**同じ図が 2 枚に写っていたら、
  それは割れた図形ではなく重なりである。片側だけを読んで済ませない。**`--range` でその
  図形だけを撮り直す
- 長い一覧表を割ると、2 枚目以降に見出し行が無い。`--title-rows 3` で全部の絵に載る
- 線の始点・終点が確定しないときは `--range` で寄る。`--target-px` を上げるより、範囲を
  狭めるほうが効果がある
- **要るのは Windows と Microsoft Excel。**無い環境では撮れないので、`kind: 未読取` のまま
  次のラウンドへ持ち越す（読めていないものを「対象外」として片付けない）
- 使い過ぎない。テキストで仕様が起こせるシートの絵は、読む予算を使うだけで何も足さない

## Excel のパース結果を読むときの前提

意味の判断はしていない。「表の型を当てる」のは整理層の仕事である
（→ [sheets.md](sheets.md)）。読む側が知っておく必要があるのは 3 つだけである。

- 縦の結合は展開済みである（「同上」の慣習の回復）。分類列の 2 行目以降にも値が入っている
  ので、そのまま読む。ただし `P012`（救出モード）の出ているブックでは広がらない
- 表記は画面に見えているとおりに直してある（日付は `2026-08-02`、パーセント書式の
  `0.153` は `15.3%`）。値そのものと食い違う表記だけを直しており、`￥1,200` の桁区切りの
  ような見た目は触っていない
- 塊の中の空行・空列は詰めていない。`at=B3:F8` の 5 列と表の 5 列が 1 対 1 に対応するので、
  番地から表の中の位置が割り出せる（空列 1 本を挟んで横に並べた別々の表を、地続きに読まない）

### すかすかな塊・大きい塊

工程表（ガントチャート）・マトリクスは、斜めや飛び飛びに値が並ぶので、枠だけ大きくて中身が
無い表になる。そういう塊は表の体裁をやめて、番地付きの箇条書きで出る。**番地は全部
付いているので落ちている値は無い。この行が出ているシートで表を探しに行かないこと。**

1,000 行／1,000 セルを超えた塊は「大きい」と申告される。**先頭だけ読んで終わりにしない。**
値は 1 つも切り詰めていないので、読む予算が足りないなら、そのシートを 1 つのまとまりとして
扱うかどうかを先に決める。途中まで読んで「読んだ」とすると、残りが `未読取` にも上がらない
まま消える。

### 取り消し線（`s1-d1`）

行を消さずに線を引くのは、いつ何をやめたかを残すためなので、資料としてはむしろ丁寧な
書き方である。機械は「廃止」とは判断せず、番地だけを出す。備考欄・改訂履歴・コードの
実在と突き合わせて決め、廃止済みなら `out_of_scope` で宣言する。**線が引いてあるだけで
落とさないこと。**消し忘れと未実装は、現行仕様のことがある。

セルの一部だけに掛かっていることがある（項目名を残して `（廃止）` だけを消す書き方）。
そのときは消してある文字が値の隣に出るので、**まるごと消した欄と読み分けること。**一部なら
残りは生きているので、`out_of_scope` に入れると現行の項目が 1 つ消える。

## 空欄に見えて空欄でないもの

**「資料に無い」と「機械が読めていない」は、次のラウンドで拾い直すかどうかが正反対になる。**
どちらも表の上では空欄にしか見えないので、必ず申告される。

| 出ているもの | 意味 | 次にやること |
| --- | --- | --- |
| `s1-f1`（計算結果の保存されていない数式） | 資料に値が無いわけではない。ツールが書き出したブック・手動計算のまま保存したブックで、合計欄・率の列がまるごと空になる | Excel で開いて上書き保存してから parse し直す。できないなら `kind: 未読取` |
| `s1-e1`（エラー値 `#REF!` `#N/A`） | 画面にもそう見えているので表にはそのまま残るが、その欄の仕様は読み取れていない | 開き直しても直らない（`f1` とは正反対）。数として使う前に `kind: 未読取` にするか、出典元へ確認する |
| 非表示の行・列 | 読むが、混ざっていることは報告する。アウトラインの折りたたみ（生きている仕様）も普通にある | 廃止済みと決まったときだけ `out_of_scope` |
| 非表示のシート（`P003`） | 読まないが、あったことは報告する。「旧版」を隠しただけのブックは実案件にごく普通にある | 中身が要るなら再表示して parse し直す |

## 表に出てこないもの

セルの値ではないところに仕様が乗っている書かれ方がある。表だけを読むと丸ごと見落とす
ので、アンカーを分けて出す。

**セルのコメント（`s1-m1`）。**決定の理由・積み残し・レビュー指摘がここに溜まる。
本文より新しいことも珍しくない。値の無いセルに付いたものも取る（空欄への指摘が最も
多い）。`返信` は前の行への回答なので、指摘だけ読んで積み残しにすると、もう決まって
いることを差し戻すことになる。`[解決済み]` は片付いた指摘なので、生きている指摘と混ぜない。

**リンクの行き先（`s1-l1`）と外部ブック参照（`P004`）。**目次シートは表示文字列だけ見ると
語の一覧にしか見えないが、実体はリンクの集まりである。行き先を落とすと、まだ集めていない
資料があること自体が分からない。外部ブック参照は表からさらに見えにくい（`='[単価表.xlsx]
単価'!B2` の値はキャッシュされていて、画面に出ているのはただの `1200`）。どちらもブックの
外を指すものが出たら、その資料も `arp4 parse` に渡したかを確かめる。

**代替テキスト（`s1-a1`）。**中身は取れないままだが、何が描いてあるかは分かる。
対象は画像だけではない。構成図はゾーンごとに 1 文添えるのが普通で、その文は箱の文字にも
表にも無い。

**印刷したときだけ見えるもの（`s1-p1`）。**文書番号・版・機密区分はフッタに入り、どの
ページにも刷られているのにセルには 1 つも書かれていない。シート 1 枚がファイル 1 本になる
以上、そのファイルが何の文書の何ページ目かは、ここにしか無い。ページ設定はシートごとに
掛かるので 1 冊の中で版が食い違っていることがあり、どれが正しいかは機械が決めない。
`印刷タイトル行` は、資料の作成者が「ここまでが見出し」と決めた範囲である。

**グラフ（`s2-k1`）。**出るのはタイトル・系列名・参照範囲の 3 つで、**描かれている数
そのものは、ここには無い。**値が要るなら、参照範囲が指しているシートのパース結果を読む
（同じブックの中に必ずあるので、絵にする必要も `未読取` を宣言する必要もない）。系列名と
タイトルは表の見出しの写しのことが多いが、単位・区分・しきい値・目標線のようにグラフ側に
しか無い語が混じる。**参照範囲の先を開いて、どちらかを確かめる** ―― 表にもあるなら図は
絵であって出典ではなく、グラフにしか無い値があるならレコードにする
（判断 → [organize.md](organize.md)「グラフのアンカーは参照範囲で決まる」）。

**ブックのプロパティ（`P005`）。**改訂履歴は人が書いた申告なので、書き忘れれば何も残らない。
プロパティは Excel が自動で書くので、改訂履歴に無い更新がここにだけ残る。

**マクロ（`P006`）。**`.xlsm` は読むが、**マクロの中身は取らない**（`vbaProject.bin` は
zip の中の OLE 複合ドキュメントで、zip としては開けない）。**「マクロが付いているだけで
中身は同じ」は表の話でしかない** ―― 採番規則・入力チェック・帳票の組み立てが**そこにしか
無い**ことがあり、そのときシートに書いてあるのは「ボタンを押す」だけである。出たら中身を
VBE で読むか、読めないなら `kind: 未読取` で宣言する（黙ると、マクロの無いブックと同じに
見える）。

## コードから取るもの

取るのは骨格だけである（クラス・メソッド・シグネチャ・戻り値・例外・取り込み）。構文木から
曖昧さなく取れるので、ここに読解は要らない。**意図の層（業務ルール・条件分岐の業務的
意味）は出さない。**コードは元ファイルがテキストなので、整理するときに原本を直接読めばよい。

塊の頭文字が出自を表す。

| 頭文字 | 中身 |
| --- | --- |
| `m1`… | クラス／モジュール関数 |
| `v1` | モジュール直下の定数（`__version__`・`EXT = ".yml"`） |
| `i1` | 取り込み（`import` / `package`）。取り込み 0 本でも出る |
| `t1` | テスト（`test_*.py` の `test` で始まる関数） |
| `p1` | コマンドの骨格（argparse の `add_parser` / `add_argument`） |
| `j1`… | Java の型 1 つ（メンバと注釈を含む） |
| `t1`/`k1`/`x1`/`c1` | DDL の表・制約・索引・コメント |

どの塊から何を起こすかは `arp4 draft` が機械で実行する → [code.md](code.md)。

**テストの期待値・フィクスチャは `--exclude` で外す。**`tests/` を丸ごと渡すと、パース結果の
正解（`dataset/正解/*.md`）を資料として拾う。除外した件数は `P014` が必ず出し、1 件にも
当たらなかったパターンも出す。

読むときの注意。

- 塊はモジュール単位のまま `行` 列を持つので、原本のどこかは 1 行ずつ読み直せる
- シグネチャは、そのまま呼び出しに写せる形で出る（`f(a, /, b=1, *, c: int = 2)`）。
  **書き換えないこと**
- **`i1` の表は 1 行 = 1 名前である。**`from arp4 import mdio, yamlio` は 2 行に割れる
  ので、`calls` も 2 本張る。どこを指すかは解いていないので、張る先は整理層が決める
- `例外` 欄には例外の型が出る（補助関数を経由していても、戻り値の型を宣言していれば辿って
  ある）。そのまま `raises` に写してよい。宣言が無いときだけ関数の名前がそのまま出るので、
  そのときは原本を読む（写すと事実と違う値になる）
- 中身のある塊しか出ない。`__init__.py` は `v1` 1 つだけになる。行数とアンカーの数は比例
  しないので、少ないことを読み落としと判断しない
- `v1` には規約と実装の都合が混ざって出る（パースは選り分けない）。内部用（先頭 `_`）も出る
- DDL はまとめずにそのまま出る。`NUMBER(11, 2)` は `NUMBER(11, 2)` のままで、「数値」へ
  まとめるのは整理層の仕事である。列の論理名は `COMMENT ON`（`c1`）にしか無いことがある
- Markdown と素のテキストは原文のまま出る（見出しごとに 1 塊）。`at` は
  `docs/決定記録.md#L30-L52` の形なので、原本の行をすぐ引ける。見出しの前の本文は
  「（前書き）」という塊になる（改訂日・適用範囲はそこに書かれることが多い）

## パース結果を編集する

パース結果は編集してよい（精度が高くないので、早い段階で直せることが要る）。ただし
2 つだけ守る。

- `<!-- a:s1-t1 at=B5:H8 -->` を**消さない・変えない**（元資料との照合が切れる）
- **編集理由をコミットメッセージに残す**（OCR の訂正と書き換えは diff で区別できない）

図の中身を人が書き起こすときは、新しいアンカーを振る（`s4-x1b` のように既存の番号と
ぶつからない形）。既存アンカーの中に混ぜると、「機械が読んだもの」と「人が起こしたもの」が
同じ出典に見える。

「機械が最初に出したもの」は、ラウンドの初回コミットとして git に残る。
