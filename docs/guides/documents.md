# 文書操作と対応範囲

Office・PDFの既存内容の編集は、本文・原本の版と旧値を照合する `documents values` を入口にします。入力形式と対応範囲は生成された[文書契約](../reference/document-contracts.md)の `value-edits` と[機能一覧](../reference/capabilities.md)を参照してください。複数ページ・複数セルの変更を1要求にまとめると、全件を検証してから保存します。不正な型、古い版、期待と違う旧値、書き戻せない文字や読み取り専用の対象があれば一切保存しません。

Excelの既存数式は `before`・`after` とも `=` 付きの数式原文を指定します。文字列セルの `=SUM(1,2)` は文字列のままです。テーブル列見出しを変えると列定義と構造化参照も更新し、空・重複・改行を含む列名は拒否します。Excel rich textは一つのrun内の曖昧でない変更に限り、共有文字列を他セルへ波及させず保持します。ふりがなやrun境界を壊す変更はExcelで行い再取り込みしてください。

Word・PowerPoint・PDFの `sheet` は抽出されたページ名、`cell` は抽出された文字列・段落・表セルの番地を指定します。Word・PowerPointは段落内の改行やタブを変更できます。PDFは元フォントで表せる文字列だけを書き戻し、改行やタブは拒否します。構造操作を記録済みの場合は先に原本へ反映して再取込・採用してから内容を編集します。

原本への反映は `review → export → 出力を開いて表示確認 → confirm-export → apply` の順です。`confirm-export` は出力ハッシュと実際に確認した範囲・担当を記録し、applyはその候補の同一バイトだけを反映します。未確認、本文・原本の版変更、候補・reportの変更は拒否します。詳しい操作は[操作リファレンス](../../surface/skills/arp4/references/operations.md)を参照してください。表示確認は人による記録であり、自動的な文字幅・はみ出し判定ではありません。固定レイアウトに任意長の文章が収まるとは保証しません。

採用済み文書から設計情報を探す手順は [文書検索](document-search.md) を参照してください。

## 本文と原本の位置対応

すべての対応文書の本文は、読む順に並ぶ文書要素として保存します。AIは通常 `content/*.yml` を読み、原本照合や配置の確認が必要なときに `layout.yml` と `extraction.json` を参照します。本文にはIDを置かず、表は値の二次元配列で保存します。セル番地やExcelの行番号・列文字は本文のキーに使いません。契約の全項目は生成リファレンスの `content` と `document-layout` を参照してください。

本文の文章は原本のセル・段落・文字列ごとに可逆な単位を保ちます。複数セルを一つの文字列へ連結しません。表は構造解釈のまとまりを使い、論理的な行・列、見出しとの関係を保持します。表・文章の間に空いた行の帯は空白要素として表し、その行数は位置情報側に置きます。結合セルが占める行は空白とみなしません。数式原文は本文、計算結果キャッシュは抽出記録に置きます。数式中のセル参照は式の一部であり、要素の配置指定ではありません。

`layout.yml` の `element_metadata` は本文の `elements` と同じ順で、ID・表の列と行・見出し関係・結合情報・数式区分を保持します。本文には値だけを置き、表内の数式も文字列で表します。未収録セルや結合の非アンカー位置は `null` で埋め、その位置への値追加は拒否します。書き戻し先、物理位置、メタデータの照合用ハッシュもlayout側で管理します。値は本文だけを編集します。要素の種類・件数や表の行列数の手動変更は拒否します。同じ形の行・列・要素を手で交換する操作は値変更と区別できず、元の位置への値変更として扱います。表と本文の区分は `documents structure-save`、行列の追加・削除・移動は専用コマンドで変更してください。構造を保存すると、現在の本文値を保持して本文と位置対応を一括更新します。行列操作が未適用なら、先に適用してから構造を保存します。

無変更の再importは本文の同一バイトを保ちます。行列の移動では本文も移動後の読む順に並びます。Gitの行差分と併せて `documents diff` の意味差分で値変更と位置変更を確認してください。Excelの行列操作のIDは適用後も再利用しません。表の内側に挿入したセルは未適用の本文でも表に含め、役割は未確定として示します。

Excelで外部編集した原本の対応付けには、現状では同じグリッドの1セル変更までを受け入れます。行列の増減や複数セルの変更は列移動との区別を証明できないため拒否し、採用済み本文を保持します。値の類似や重複見出しから同一性を推測しません。

保存形式を変更したため、以前の本文形式は読み込みません。元の管理データを保管した上で、新しい文書プロジェクトへ原本から取り込み直してください。未適用の本文編集やレビューは自動移行されません。

Word・PowerPoint・PDF・テキスト文書も、本文と位置情報を同じ組で保存・検証します。WordとPowerPointの行編集、スライドの複製・削除では、本文と位置情報を一括更新します。Excel以外の再取り込みでは新しい抽出結果から位置情報を再構築します。TXT・Markdown・CSV・TSVの本文YAMLは引き続き読み取り用の派生データであり、編集は原本に行って再取り込みしてください。

識別用IDは内容ハッシュではなく、内部の行・列やDrawingMLの識別情報から読み取れる文字列を作ります。本文の値変更やARPの行列操作で対象を取り違えないよう、現在の物理座標ではなく内部IDを使います。区切りと入力文字の混同を避けるためエスケープします。原本の版とメタデータの整合性を検証するSHA-256は引き続き保持します。

### 画像・グラフ・図形の参照

本文には画像・グラフ・その他の図形の参照要素も `image: null`・`chart: null`・`drawing: null` として置きます。同じ配列位置の `element_metadata` の `ref` は同じページの `layout.yml` の `sheets[page_id].visuals[ref]` を指します。画像実体は参照先の `asset`（文書フォルダからの相対パス）、グラフXMLと参照式は `chart_part` と一致する `extraction.json` の `chart_parts` から取得します。参照先の `source` は抽出結果内のDrawingMLオブジェクトへのJSON Pointerです。OCRは抽出結果のassets、解釈・レビューは `documents structure-read` のvisualsをこのsourceで照合します。

図形内の文字は編集可能なtextとして一度だけ本文に置き、メタデータの `visual` で対応する参照要素へ結びます。画像のOCRやグラフXMLを本文の文字へ複製しません。参照要素の種類・null値の手編集は拒否します。画像差し替えやグラフ編集はこの参照形式だけでは行いません。

読む順はセルアンカーを基準とした仮の順序です。行列操作では、移動・サイズ変更・固定というExcelの配置設定に従ってアンカーを更新します。絶対座標だけの図形はセル位置へ換算せず、位置側で `order_basis: unpositioned` として本文末尾に置きます。グループ内の図形には親参照を保持し、グループ内の細かな位置は抽出結果のtransformで確認します。重なった図形や複雑な図の意味上の読み順は構造レビューで確認してください。

## 形式別の対応

| 原本 | 取り込み | 編集と反映 |
|---|---|---|
| Excel (`.xlsx` / `.xlsm` / `.xltx` / `.xltm`) | セル値・数式原文・結合範囲・図形情報・埋め込み画像（Windowsでは画像の自動OCRも実施） | 通常セル値、既存数式の置き換え、図形の文字、明示した行列の追加削除、PNG追加 |
| Word (`.docx` / `.docm` / `.dotx` / `.dotm`) | 段落、行・列・結合を保った表、画像とOCR、フィールド命令、印刷セクション設定 | 段落・セルの文字列を編集し（段落内の改行・タブの追加削除を含む）、変更箇所のrunだけを書き換えて同形式へ書き戻す（フィールドの表示結果を除く） |
| PowerPoint (`.pptx`) | スライド本文・表・ノートの段落と表のセル | 段落内の文字列・改行・タブを編集し、段落・表の行とスライドを追加削除して、同形式へ書き戻す |
| PDF (`.pdf`) | ページのテキスト描画命令内の文字列 | 元フォントで表現できる文字列へ置換し、同形式へ書き戻す |
| TXT・Markdown・CSV・TSV | UTF-8の本文と構造 | 原本を直接編集して同じパスのまま再取り込み。export/applyは未対応 |

形式間の変換は行いません。表は概要であり、抽出対象外と書き戻し条件は以下を確認してください。

## Office・PDFと共通の制限

- 対応する取り込みは `.xlsx` / `.xlsm` / `.xltx` / `.xltm` / `.docx` / `.docm` / `.dotx` / `.dotm` / `.pptx` / `.pdf` / `.txt` / `.md` / `.csv` / `.tsv` です。テンプレート（`.xltx` / `.xltm` / `.dotx` / `.dotm`）は通常のブック・文書と同じ本体を持つため同じ扱いです。暗号化されたファイル（パスワード・IRM・秘密度ラベル）、バイナリ形式（`.xls` / `.xlsb` / `.doc` / `.ppt`、または拡張子だけOpen XMLのバイナリ）、Strict Open XML形式は読み込めません。取り込み時のエラーに従い、Officeで保護を外すか標準のOpen XML形式で保存し直したコピーを取り込んでください。テキスト・Markdown・CSV・TSVはUTF-8で構造に応じて取り込み、原本を直接編集して再取込します（export/applyは未対応）。詳細は後述のテキスト原本の説明を参照してください。Excelはセル値・数式原文・結合範囲を抽出します。共有数式の各セルはExcelと同じく相対参照を移動した数式として示し、ふりがな（日本語入力で記録される読み）はセルの値に含めません。日付・時刻はシリアル値と表示形式で示します（ISO形式の日付で保存されたセル `t="d"` もシリアル値にします）。セル内に配置した画像とリンクされたデータ型（株価・地理など）は値がセルの外にあるため抽出せず、セルの位置を抽出の注意事項（R001）に記録します。スライサー・タイムライン等が古いExcel向けに持つ説明用の図形は抽出しません。書式コードを持たない東アジア向けの組み込み表示形式（ID 27〜36・50〜58）は日本語版Excelの定義で示し、1904年日付系のブックはその旨を抽出の注意事項（R001）に記録します。メモ・スレッドコメント（シートの `comments`）、図形に割り当てたマクロ（`macro`）、フォームコントロールの種類・リンク先セル・選択肢範囲（`control`）も抽出します。ActiveXコントロールの内部設定は解析せず、部品名とSHA-256を `opaque_parts` に記録します。印刷設定は `print_settings`、グラフ部品のXMLと参照式は `chart_parts` に読み取り専用で記録します。原本の外観も確認してください。
- Word/PPTX/PDFも[導入ガイド](rust-preview.md) と同じ `import → YAML編集 → record → adopt → review → export` を使います。出力は原本と同じ拡張子の新規ファイルを `.arp/cache/export/` に指定します。形式間の変換は行いません。詳細と検証手順は [複数形式の往復テスト](../../examples/document-roundtrip/README.md) を参照してください。
- Wordは本文・表・テキストボックス・ヘッダー・フッター・脚注・文末脚注・コメントを段落と表のセル単位で抽出します。表の外の段落は1段落1行でA列に並び、表は行・列の位置を保ち、横・縦の結合セルを `merges`、表の範囲と見出し行の推定を `tables` に記録します。構造解釈はこの表定義を使うため、Wordの表もExcelの表と同じく見出しと値の対応をレビューできます。見出し行はWordの「見出し行の繰り返し」、太字・網掛けの先頭行、3列以上の表の先頭行から推定します（2列の表は項目と値の一覧が多いため見出しなし）。セル内の段落・改行は改行、タブはタブ文字で表し、入れ子の表は外側のセルの本文に含めます。ルビ（ふりがな）の読み、変更履歴で削除・移動された元の文字、隠し文字、コンテンツコントロールの入力案内（「クリックまたはタップして…」）、フィールド命令の中にある内側のフィールドの結果はWordの本文に表示されないため抽出しません。改ページ・段区切りは改行として扱いません。改行しないハイフン・記号（`w:sym`）・位置指定タブ・数式の文字は本文に含めますが、Wordが描く文字のため置換できません。書き戻しは変更前後の差分を取り、変更箇所を含むrunだけを書き換えます。複数のrunにまたがる変更は、Wordで範囲選択して入力したときと同じく先頭runの書式になります。段落内の改行・タブは追加・削除・置換でき、変更箇所のrunに改行（`w:br`）・タブ（`w:tab`）として書き込みます。YAMLでは段落の区切りも段落内の改行も `\n` で表すため、新しく書いた改行は段落内の改行になります。段落の分割・結合となる変更は拒否します。前後に同じ文字列が続き、変更がどのrunに当たるかで各runに残る文字が変わる編集（太字の「注意」と通常の「注意事項」が並ぶ所で「注意」を1つ消す等）も、残る書式が変わるため拒否します。繰り返さない文字を含めて変更するか、Wordで編集してください。表紙のタイトル・作成者など、文書のデータと連携したテキストのコンテンツコントロールを編集すると、連携先のデータ（文書のプロパティまたはカスタムXML）も同じ文字に書き換え、同じデータと連携した他のコントロール（ヘッダーの表題など）も同じ文字にします。Wordは開くときにデータからコントロールの文字を戻すためです。同じデータと連携したコントロールを異なる文字に編集した場合、複数行を許可していないコントロールに改行を入れた場合、日付・リスト・画像などのコントロール（表示とデータの形式が異なる）は拒否します。PPTXもWordと同じく、スライドとノートの表の外の段落を1段落1行でA列に、表を行・列の位置と結合を保って並べます（段落は図形をまたいでスライドの上から順に数えます）。書き戻しは変更箇所を含むrunだけを書き換え、段落内の改行・タブを追加・削除・置換できます。新しい改行は同じ書式のrunの間の改行（`a:br`）として書き込みます。段落の分割・結合となる変更は拒否します。スライドショーで非表示のスライドはシートの `state` を `hidden` とし、表の結合で隠れたセルの文字と、数式を含む図形の互換用の代替表示は抽出しません。Wordはテキストボックスを表示用（DrawingML）と互換用（VML）の2組で保存するため、表示される1組だけを抽出し、書き戻しでは両方を同じ文字にします。2組の文字列の数が異なる場合は書き戻しを拒否します。UTF-16で保存された部品や、参照先がパーセントエンコードされた部品も読み込み、書き戻しでは元の文字コードを保ちます。その他のZIP部品とrunの書式を保持します。PDFは各ページのテキスト描画命令内の文字列を編集し、原本のフォント・座標・画像等のオブジェクトを保持します。文字の意味はフォントのToUnicode対応表を優先して読み、対応表にない文字コードは1文字ずつ代替文字（U+FFFD）にします。スキャンPDFのOCR層など見えない描画モードの文字は抽出しますが、書き換えても表示が変わらないため書き戻しを拒否します。画像PDFのOCR、PDFのForm XObject内の文字・注釈・フォーム、PPTXのマスター・グラフ内部は抽出対象外です。PPTXのノートは全スライドの後に `notes-N`（Nはスライド番号）として抽出し、スライドと同じくrun単位で書き戻せます。ノートのスライド番号・日付・ヘッダー・フッターはノートマスターから表示されるため抽出しません。
Wordの `word/media/` にある画像は取り込み時に `assets/` に保存し、Windowsでは自動OCRの結果を抽出JSONの `assets` に記録します。構造解釈では画像を確認対象のvisualとして扱います。Wordのフィールド命令は表示結果とは分けて `field_codes` に読み取り専用で記録します。印刷に関するセクション設定は `print_settings` に原本XMLと部品名を記録します。

- Excel以外も本文YAMLの `elements` に値を保存し、原本との対応は `layout.yml` に分離します。位置情報側のWordの `rN` は段落・表の行を上から数えた番号、`A` 以降の列は表の列で、Excelの物理セルではありません。PPTXの `rN` も段落・表の行の番号で、PDFの `rN/A` は文字列の通し番号です。Wordの `document.yml` は本文、PPTXの `slide-N.yml` はスライド、`notes-N.yml` はそのノート、PDFの `page-N.yml` はページに対応します。文字列を空にするには `""` を指定してください。WordとPowerPointの段落（表の外）と表の行は、Excelと同じ `documents rows insert|delete` で追加・削除できます。追加した行は既定で上の行（`--style-from` で指定した行）の段落・表の行を複製し、段落と各セルの書式と先頭runの書式を保って文字列だけを入れ替えます。すべての行を削除した表は表ごと削除します。テキストボックス内の段落、セクション区切りを持つ段落、縦に結合したセルを含む表の行の操作と、Wordの列の追加削除は拒否します。PowerPointのスライドは `documents slides insert|delete` で複製・削除できます。複製したスライドは操作IDで呼び、本文は `content/<操作ID>.yml`（ノートは `content/notes-<操作ID>.yml`）に複製元の値を写して作るので、そのページを編集して文字を書き換えます。グラフ・SmartArt・埋め込みオブジェクトは複製し、レイアウト・画像は共有し、コメントは複製しません。削除はスライドとそれだけが使う部品（ノート・グラフ・コメント等）を取り除きます。他のスライドからリンクされているスライドの削除と、目的別スライドショーが空になる削除は拒否します。PPTXのrun単位の追加削除とPDFのページの追加削除は未対応です。列の追加削除とPNG画像の追加はExcelのみ対応します。
- 本文YAMLを手で編集するときは、書いた文字と読み取られる値が異なる書き方を拒否します。値の後ろのコメント（`Issue #12` は `Issue` と読まれるため）、引用符なしで次の行へ続く値、`null` 以外で書いた空値（`~`・`NULL`・`Null`・値なし）、値を変換するタグ（`!!str`・`!!binary` など）、アンカー・エイリアス・マージキー（`<<`）が対象です。`#` を含む文字列や `NULL` という文字列は引用符で囲み、Excelのセルを空にするには `null` と書きます。`true`/`false` だけが真偽値で、`yes`・`N` などは文字列、`010` は10進数として読みます。文書IDである原本のパスは、既存の文書と大文字小文字だけが異なるフォルダ名・ファイル名を併用できません（WindowsとmacOSのファイル名が大文字小文字を区別しないため）。
- Excelテーブルの見出し行のセルを編集すると、テーブル定義の列名も変更し、ブック内の全シートの数式・計算列と集計行の数式・名前定義にある構造化参照（`テーブル名[列名]`）を新しい列名に置き換えます。列名は空でない255文字以内の文字列で、改行・タブを含まず、同じテーブルの他の列名と大文字小文字を区別せずに重複できません。集計行のラベルのセル（関数を表示しないセル）を編集すると、テーブル定義の集計ラベルも変更します。集計行で関数を表示するセルの編集は拒否するため、Excelで変更してください。行・列の追加で増えた列の見出しは、新しい列名として書き込みます。
- Excelで次のセルは書き戻しません。配列数式・スピル・What-Ifデータテーブル・ピボットテーブルの範囲内のセル（Excelが再計算で上書きするため）です。取り込み時に書き戻し対象外として記録し、編集は検証で拒否します。行・列の削除操作で消える行・列は本文からも削除してください。本文に残した場合は拒否します。セル文字列の `_x000D_` など、Excelが `_xHHHH_` で保存した文字は元の文字として抽出し、書き戻しでは `_x0041_` のような文字列をExcelが変換しないよう保存します。書き戻し時の再計算指定は、反復計算・表示桁数での計算・手動計算などブックの計算設定を保ったまま追加します。
- PowerPointの段落は、追加すると書式元（`--style-from`、既定は上の行）の段落と同じ図形に入り、その段落の書式（箇条書きのレベル等）と先頭runの書式を写します。図形のすべての段落を削除した場合は空の段落を1つ残し、すべての行を削除した表は表ごと削除します。縦に結合したセルを含む表の行の操作は拒否します。PDFの置換文字列では改行・タブを追加できません。PDFは元フォントの文字コードで往復変換できない変更を拒否します。元の文字列の文字コードが文字と1対1に対応しない場合（未定義の文字コード、縦書き用字形など同じ文字に複数の字形がある場合）も、編集しない文字が変わるため拒否します。フォントがサブセット埋め込み（`ABCDEF+` で始まるフォント名）の場合は、文書内でそのフォントが描いている文字だけを使えます。描画命令を最後まで解析できないページ（抽出の注意事項に記録）は書き戻せません。インライン画像（`BI` ～ `EI`）を含むページは、画像を元のバイト列のまま残して書き戻します。暗号化PDF（パスワードなしで開ける編集・印刷制限付きのPDFを含む）と署名付きPDF/Officeの書き戻しも対象外です。PPTXのスライド番号・日付などのフィールドはPowerPointが再計算するため、その文字の書き戻しを拒否します。Wordのフィールドの表示結果（日付・ページ番号・目次・相互参照等）はWordが開いたときや印刷時に再計算して編集が消えるため、書き戻し時に拒否します。フィールドはWordで編集してください。`.docm` / `.dotm` のVBAプロジェクトは読み込まず、書き戻しでもそのまま保持します。Wordの再組版、PPTX/PDFの文字のはみ出し・重なりは出力ファイルを開いて確認してください。PDFの自動改行・レイアウト再構築は行いません。
- Excelの書き戻しは通常セルの値、既存数式の置き換え（次項）、明示した行・列の追加削除、`assets/` のPNG画像を `add_image` 操作で指定したセル範囲へ追加する処理に対応します。既存画像・図形のセルアンカーは、Excelの配置設定（セルに合わせて移動とサイズ変更／移動のみ／固定）に従って構造変更に追従しますが、画像の完全な外観再構築、回転・トリミング・絶対座標、図形の追加・削除・移動・書式の編集、COMによる書き戻しは未対応です。文字を持つ図形は本文YAMLの `shapes` 表（`shape-<図形ID>` の `text`）に抽出し、編集すると変更箇所を含むrunだけを書き換えます（先頭runの書式になる点はWordと同じです）。行ごとに差分を取るため複数行を同時に編集できますが、改行・段落の数は変えられません。フィールドの文字は書き戻しません。構造変更時の参照の扱いは次項を参照してください。数式のキャッシュは無効化し、Excel起動時の再計算を指定します。マクロ部品は保持対象ですが、マクロ実行の検証はしていません。ブック内のマクロシート（Excel 4.0）・ダイアログシート・グラフシートはセルを持つワークシートではないため抽出せず、抽出の注意事項（R001）にシート名を記録します。これらの部品は書き戻しでも変更しません。フォームコントロール（マクロ実行ボタン等）の `mc:AlternateContent` は `mc:Choice` を優先して図形を1件として抽出します。
- 行・列の追加削除は、Excel自身の挿入・削除と同じ結果になるようにセル位置を持つ部品を更新します。対象は全シートの数式（共有数式は必要に応じて個別の数式に展開）、名前付き範囲・印刷範囲・印刷タイトル、条件付き書式・入力規則（x14拡張を含む）、ハイパーリンクのセル、オートフィルターと並べ替え、結合セル、列幅、スパークライン、Excelテーブル（他シートのテーブルの計算列・集計行の数式を含む）、ピボットの参照元範囲と配置、グラフ系列、図形のアンカーとセル参照（`textlink`）、改ページ、条件付き書式のしきい値（`cfvo`）、What-Ifデータテーブルの範囲と入力セル、メモ・スレッドコメントのセル（削除されたセルのメモ・コメントは削除）、フォームコントロールと埋め込みオブジェクトのアンカー（配置設定に従う）とリンク先セル・選択肢範囲（他シートのコントロールを含む）です。範囲の内側への挿入は範囲を広げ、一部の削除は範囲を縮め、全体が削除された参照は `#REF!` になります。結合セルの内側に挿入した行・列のセルは広がった結合に隠れるため、そこへの値の書き込みは拒否します。Excelと同様に、条件付き書式・入力規則・列幅・スパークラインは直前の行・列から挿入行・列へ引き継ぎ（非表示の列の直後に挿入した列は表示されます）、挿入行・列に書き込む値は上の行・左の列のセルの書式、それ以外で新しく作るセルは行、次に列の書式を使います。テーブル内の挿入行には計算列の数式を入れます。テーブルの列を削除すると、その列への構造化参照は `#REF!` になります。ハイパーリンクの移動先（`location`）はExcelと同じく書き換えず、ピボットのキャッシュは更新しません。計算チェーン（`calcChain.xml`）は削除し、Excelが再生成します。テーブル内に挿入した列の既定の見出しは `Column1` 等で、ExcelのUI言語による名前（`列2` 等）とは異なることがあります。
- Excelが拒否する変更（テーブルの見出し行・集計行・全データ行の削除、テーブル全体の削除、ピボットテーブルや配列数式の範囲を横切る変更、ピボットの参照元全体の削除、空でないセルをシートの最終行・最終列の外へ押し出す挿入）はARPも拒否します。
- 行・列の追加削除は、ARPが移動できないセル位置を他の部品が持つブックでは拒否します。対象はVBAプロジェクト（コード内のセル番地）、マクロシート、ダイアログシート、ActiveXコントロール（リンク先セルをバイナリ部品に保持することがあるため）です。データテーブルの範囲を横切る変更と入力セルの削除も拒否します。`documents export` の反映計画の時点でエラーになり、原本と出力は作成・変更しません。この場合、行・列の変更はExcelで行って再取り込みしてください。セル値の編集は引き続き利用できます。WindowsのExcel COMは `spec structure render` の読み取り専用描画に使用します。
- 数式のあるセルは、本文要素または表セルの `formula` に `=` から始まる数式原文を保持します。最後に計算された結果は `extraction.json` に置きます。数式を変更するときは本文の `formula` を編集します。書き戻しでは数式を置き換えて古い計算結果を消し、Excel起動時の再計算を指定します。数式はYAMLに表示されたファイル内の表記で書きます（英語の関数名、引数の区切りはカンマ、Excel 2010以降の関数は `_xlfn.XLOOKUP(` のように `_xlfn.` 付き）。`_xlfn.` のない新しい関数、閉じていない括弧・引用符、スピルする関数（`FILTER`・`SORT`・`UNIQUE`・`SEQUENCE` 等）、`LET`・`LAMBDA`、スピル範囲演算子 `#` と共通部分演算子 `@` は、Excelが別の数式として読むため拒否します。これらはExcelで入力して再取り込みしてください。数式の書き戻しは既存の数式セルだけが対象で、値のセルを数式にすること、数式を値にすることはできません。配列数式・スピル・データテーブル・結合で隠れたセルの数式も書き戻し対象外です。共有数式の一部を変更すると、そのシートの共有数式を個別の数式に展開します。数式は原本の行・列の位置で書き、同じ文書の行・列の追加削除では他の数式と同じく参照を移動します。削除される行・列の数式は変更できません。
- Excelの見出し推定・空行ごとの表分割は未対応です。元の行・列を保つ表を生成します。
- `resume`、`edit-base/plan/apply`、文書内のローカルリンクを持つ本文の検証は未対応です。`spec` によるメタモデル検証と Markdown 設計書生成は [仕様書生成](../reference/specifications.md)を参照してください。
- 保存形式は `contracts/document-schemas.json`、出典・成形とレビューのハッシュは正規化した JSON を基準にします。
- diffは本文・対応表・除外理由・原本情報・画像ハッシュを比較します。画像の見た目は比較しません。
  通常応答は `items` に変更内容を出力します。`--out <新規パス>` で全差分JSON、`--format markdown --out <新規パス>` で全差分Markdownを保存できます。標準出力は保存先を示すJSONです。
- `record`・`adopt`・`review` はフォルダIDまたは `--all` で、その操作を待つ状態の文書をまとめて処理できます。形式を問わず同じです。手順と `--dry-run --out` / `--expect` による対象の固定は [導入ガイド](rust-preview.md) を参照してください。計画ファイルの形式は `contracts/document-schemas.json` の `batch-plan` です。


Excelの表を原本の表示と結び付け、書き戻しから独立して整理する手順は[原本を変更しない整理](document-structure.md)を参照してください。修正記録は文書モデルの `mappings.yml` に保存し、`documents structure-read/save` で整理ビューを編集します。WindowsとデスクトップExcelがあれば指定範囲をPNGに描画でき、領域・版の対応と多段見出し・読取レビュー状態を保持できます。図と画像の読取記録、他形式の領域登録にも対応します。詳しくは[構造解釈](document-structure.md)を参照してください。[文書表現案](../design/visual-document-model.md)には今後の拡張案も記載しています。

## テキスト・Markdown・CSV・TSV原本

`.txt` / `.md` / `.csv` / `.tsv` は正式な文書原本として取り込めます。UTF-8（BOMあり・なし）、最大32 MiBに対応します。TXT・Markdownは最大1,048,576行、CSV・TSVは最大16,384列・1,048,576フィールドです。文字コードを推測・変換せず、非UTF-8やNULを含む入力は拒否します。Shift_JIS・UTF-16は、利用者が原本をUTF-8に変換してから取り込んでください。

```powershell
arp4 documents import docs/requirements.md --root C:/my-project
# 文書IDは docs/ からの相対パス requirements.md。候補の内容を確認し、判断記録を保存して採用する
arp4 documents record requirements.md --model <モデル名> --actor <担当> --prompt C:/my-project/review.txt --root C:/my-project
arp4 documents adopt requirements.md --root C:/my-project
arp4 documents review requirements.md --reviewer <確認担当> --root C:/my-project
arp4 spec capture --extraction C:/my-project/.arp/documents/requirements.md/extraction.json --out C:/my-project/.arp/cache/requirements-input.json
```

Officeと同じく、抽出結果を `spec capture` から要件・仕様の根拠として利用できます。レビュー・修正時だけの参考資料にする `spec workflow init --reference` とは用途が異なります。

本文は原本を直接編集します。編集後は同じパスのまま再度importし、候補を確認してrecord・adoptします。原本のハッシュが変わると以前の取込状態は古くなり、新しい候補に以前のレビューは引き継ぎません。再取込後のextractionからcaptureし直して要件・仕様のレビューを進めます。

`.arp/documents/<文書ID>/content/` に確認用の派生ビューを生成します。対応付けられた本文の変更はcheck時に拒否します。これらの原本に対する `export` / `apply` は未対応です。ARPは原本を書き換えないため、BOM・改行・末尾改行はそのまま残ります。外部エディタでの変更はそのエディタの保存設定に従います。

TXTは論理シート `text` の `A1`・`A2`…が原本の行番号です。空行も数え、LF・CRLF・CRを行区切りとして扱います。抽出値から行区切りと先頭BOMを除き、その他の空白・タブは保持します。空ファイルはimportできますが、抽出可能な本文がないためspec captureは拒否します。

MarkdownはCommonMarkのブロック構造と表・タスクリスト・脚注・先頭の `---` で囲んだYAMLフロントマター（種類 `front_matter`）等の拡張を解析します。論理シート `text` の `A1`等はブロック番号です。見出し階層、段落、リスト、表、コード、引用等を識別し、本文はMarkdown記法を含む原文のまま保持します。複数行の段落、リスト全体、表全体、コードブロックをそれぞれ一つの出典とし、表には列見出しも付けます。コード内の `#` を見出しとして扱いません。リンク定義などパーサーのブロック外にある非空白の原文も出典として残します。リンク先や画像は読み込みません。

各出典の `position` はブロックの種類・見出し階層・行範囲（1始まり、両端含む）・UTF-8バイト範囲（0始まり、終端を含まない、BOMを含む原本基準）を持ちます。capture後の `context.position` と、抽出・レビューpacketの `sources.columns` にある `position` にも渡します。位置は原本ハッシュと組み合わせて使い、永続IDとはみなしません。

## 再取込の変更追跡

原本を編集して同じパスのままimportした後、採用前に候補の差分を確認します。

```powershell
arp4 documents diff <文書ID> --root C:/my-project
# JSONの全詳細、または保存するMarkdownレポート
arp4 documents diff <文書ID> --full --root C:/my-project
arp4 documents diff <文書ID> --format markdown --out changes.md --root C:/my-project
```

通常のデータ差分に加え、TXT・Markdown・CSV・TSVの候補には `source_impact` が含まれます。本文・構造・見出しを比較し、以下を区別します。

| kind | 意味 |
|---|---|
| `moved` | 同じ見出し・構造・本文で、一意に対応する出典の位置移動 |
| `reordered` | 同じ出典同士の相対的な順番が変更された |
| `context_changed` | 一意に一致する本文が別の見出し・列文脈等へ移動した |
| `modified_candidate` | 同じ文脈に残った旧・新出典が各1件。本文変更の対応候補で、要確認 |
| `ambiguous` | 重複本文や複数の変更候補があり、対応を確定できない |
| `added` / `removed` | 追加・削除 |
| `stale_evidence` | レジストリの根拠が今回の比較元とは異なる版を参照している |

`.arp/registry/` があれば根拠の版を照合し、同じ見出し範囲（配下の小見出しを含む）の項目と要件参照・関連参照を通じた依存項目を `affected_entries` に表示します。本文変更・追加・削除・順序や文脈の変更・曖昧な対応は `review_required: true` です。TXT・CSVには見出し階層がないため、本文変更時は文書全体の根拠付き項目を保守的に対象にします。

このレポートは再レビュー対象の判断に使います。根拠ID・スナップショット・承認状態を自動更新したり、レビュー済み状態を新しい候補へ移したりはしません。`authority_changed: true` の場合は取込候補を作った後に採用側も変化しているため、最新の原本と採用状態から候補を作り直してください。

## CSV・TSV

CSVはカンマ、TSVはタブを区切り文字とします。先頭行も通常のレコードとして取り込み、ヘッダーや型を推測しません。全フィールドを文字列として保持するため、`001`・`false`・数式に見える文字列も変換・実行しません。引用符内の区切り文字と改行、二重引用符のエスケープ、空欄に対応します。空の物理行はレコードに数えませんが、`""` の空フィールドは保持します。列数不一致・閉じていない引用符・引用符外の不正な文字は拒否します。

論理シート `records` の行はレコード番号、列はフィールド番号です。`position.record`・`position.column` にその番号を持ち、行・バイト範囲は引用符を含む原本フィールドの範囲です。抽出値はCSV構文を復号した文字列なので、引用符やエスケープを含む原本断片そのものとは区別します。先頭行もcaptureの出典になり、空フィールドはextractionに保持します（空文字自体はcaptureの引用対象になりません）。

JSON・YAMLの形式別対応は含みません。`.arp/` 内の生成物は原本として取り込めません。
