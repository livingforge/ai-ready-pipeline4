# ADR-002: 埋め込みの提供元

- 状態: 採用
- 決定日: 2025-11-27
- 決めた人: 田村・小島（AI基盤グループ）、承認: 大城（部長）
- 関連: ADR-004（テナントの分離）

## 背景

埋め込みモデルをどこから調達するかを決める必要がある。条件は 3 つ。

1. 日本語の技術文書で精度が出ること（保守マニュアル・不具合報告・契約書）
2. **極秘の情報を扱えること** —— 外部へ出せないデータがある
3. 運用の手間が小さいこと（6 名の体制で回す）

2 が効く。法務部の契約書は社内の情報区分規程で「極秘」にあたり、
外部のサービスへ送出できない。

## 決めたこと

**外部 API と社内ホストを併用する。機密区分で経路を分ける。**

| 機密区分 | 経路 | モデル |
| --- | --- | --- |
| 10 一般 / 20 社外秘 | Voyage AI（外部 API） | `voyage-4` |
| 30 極秘 | 社内 GPU（A100 x2） | `voyage-4-nano` |

`voyage-4-nano` はオープンウェイト（Apache-2.0）なので社内に置ける。
**極秘を扱える唯一の選択肢**である。

経路の判断は 1 か所に集約する（`embed/router.py`）。区分の判定
（`tenant/classification.py`）と振り分けを分けるのは、規程が変わった
ときに直す場所を 1 つにするため。

## 選ばなかったもの

**すべて社内ホストにする**
: A100 が 2 枚しかなく、全部門の取り込みを捌けない。品質保証部の
  月 200 万チャンクだけで GPU が埋まる。

**すべて外部 API にする**
: 極秘を扱えない。法務部が使えないなら基盤にする意味が薄い。

**極秘だけ諦める（法務部を対象外にする）**
: 稟議の前提が「全社の文書検索」なので、いちばん要望の強い部門を
  外すのは通らない。

## 結果として

- 精度は区分によって差が出る。極秘は落ちる（PoC の評価で 0.82 → 0.71）
  —— **これは法務部と合意した上での運用**である
- 社内 GPU の占有秒を計測してチャージバックに使う
- `input_type`（`query` / `document`）を必ず指定する。PoC の初期に
  これを省いていて精度が出ず、**原因を探すのに 2 週間かかった**

## 追記（2026-03-02）

法務部から「`voyage-law-2`（法務・長文向け）のほうが精度が高いのでは」
という問い合わせがあった。**そのとおりだが極秘では使えない**（外部 API
のみの提供）。台帳には載せてあるが、法務部のテナントでは指定できない
（`registry.resolve` が弾く）。

営業本部（社外秘）でなら使える。検討中。
