# ADR-008: 部門へのチャージバック

- 状態: 採用
- 決定日: 2026-03-05
- 決めた人: 田村（AI基盤グループ）、経理部と合意、承認: 大城（部長）

## 背景

外部 API の費用と社内 GPU の費用は、いったん AI基盤グループの予算で
立て替えている。稟議の条件に「利用部門へ按分すること」が入っており、
2026 年度から実施する必要がある。

## 決めたこと

**使った量で按分する。単位は 4 つ。**

| 品目 | 単位 |
| --- | --- |
| エンベディング | 埋め込んだチャンク数 |
| 検索 | 呼び出し回数 |
| リランク | 呼び出し回数 |
| 社内 GPU | 占有秒 |

**単価は翌月に決める。** 外部 API の請求は月末に確定するので、実績を
按分して単価を出す。そのため締めは翌月 5 営業日目に回す。

**円未満は切り捨てる。端数は基盤側が持つ。** 1 円単位で割り振ると合計が
合わなくなる。経理部と合意済み。

**締めたあとの月は書き換えない。** 経理へ渡したあとに数字が動くと
突合が壊れる。訂正は翌月で調整する。

## 選ばなかったもの

**トークン数で数える**
: 提供元の請求はトークン建てだが、利用部門にトークンは分かりにくい。
  「何件入れたか」のほうが説明できる。

**定額で分ける**
: 使っていない部門が払うことになる。稟議の「使った量で」に反する。

**実費をそのまま請求する**
: 為替と提供元の値上げがそのまま各部門に効く。単価を月次で決める
  形にして、変動を基盤側で吸収する。

## 結果として

- 日次で計測し、月次で締める（`billing/`）
- 経理へは Shift_JIS の CSV で渡す（会計システムの様式）
- 各部門は `GET /v1/usage` で使用量を確認できる

## ★ 書かれていないこと

- **キャッシュに当たった分は課金しない。** 提供元へ投げていないので
  費用が発生していない、というのが理由。**利用申請の説明資料には
  書いていない**ので、「思ったより請求が少ない」と言われるたびに
  口頭で説明している
- **金額は API で返さない。** 締める前の暫定値が独り歩きして経理と
  揉めたことがあり、返さない形にした。経緯は
  `docs/runbook/billing.md` にしかない
- **端数の扱い**もこの ADR に 1 行あるだけで、実際の計算
  （`billing/allocate.py` の `residual`）と対応づけられていない
