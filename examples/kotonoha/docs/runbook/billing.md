# 月次の締めと請求

最終更新: 2026-06-08（田村）
関連: ADR-008（部門へのチャージバック）

## いつやるか

**翌月 5 営業日目。** 外部 API の請求が月末に確定してからでないと
単価を決められない。

## 手順

1. **外部 API の請求を確認する。** Voyage AI のコンソールから前月分の
   請求額を控える。社内 GPU の電力と減価償却は情報システム部から
   毎月 3 営業日目に来る。

2. **単価を登録する。** 請求額を前月の実績で割って単価を出す。

   ```sh
   kotonoha price set --kind embed_chunk --from 2026-07-01 --price 0.0182
   ```

   **古い行の `valid_to` を先に閉じること。** 期間の重なりは弾かないので、
   閉じ忘れると新しいほうが引かれるとは限らない。

3. **締める。**

   ```sh
   kotonoha close --month 202606
   ```

4. **CSV を書き出して経理へ渡す。**

   ```sh
   kotonoha export --month 202606 --out /tmp/202606.csv
   ```

   Shift_JIS で出る。**渡せない文字があるとエラーで止まる** ——
   静かに化けたまま渡すと原価センタが取り違えられるため。
   止まったらテナント名か原価センタに機種依存文字が入っている。

5. **原価センタごとの合計を経理と突き合わせる。**

## 端数の扱い

**円未満は切り捨て、端数は AI基盤グループが持つ。** 経理部と合意済み。

按分後の合計と実額の差は `residual` で出る。

- 正なら基盤の持ち出し
- 負なら取りすぎ → **翌月の単価で調整する**

取りすぎが 3 か月続いたら単価を見直すこと。

## 締めたあとに間違いが分かったら

**締めた月は書き換えない。** 経理へ渡したあとに数字が動くと突合が壊れる。
訂正は翌月で調整する。

経理へ渡す前なら取り消せる。

```sh
kotonoha close --reopen --tenant qa-defect --month 202606
```

## よくある問い合わせ

**「思ったより請求が少ない」**
: キャッシュに当たった分を課金していない。同じ通達文や定型の前書きが
  複数の文書に入っていると、2 件目以降は提供元へ投げていないので
  費用が発生していない。**利用申請の説明資料に書いていない**ので、
  毎回このとおり口頭で説明している。書き足すこと（未対応）。

**「今月いくら掛かっているか API で見たい」**
: **返していない。** 2026/05 に暫定値を返していたとき、締める前の
  数字を各部門が予算管理に使ってしまい、締めたあとの確定値と合わずに
  経理と揉めた。それ以来、`GET /v1/usage` は使用量だけを返して金額は
  返していない。金額が要るなら締めたあとに基盤グループへ問い合わせて
  もらう。
