# 取り込みの運用

最終更新: 2026-05-30（小島）

## 詰まったとき

滞留のアラートは「キュー長 > 500」または「最古の待ち時間 > 30 分」で鳴る
（SLO の滞留 30 分に対応）。

1. **キューの深さを見る。**

   ```sh
   kubectl -n kotonoha exec deploy/kotonoha-api -- kotonoha queue stats
   ```

2. **どのテナントで詰まっているか。** 品質保証部の同期（毎晩 2 時）で
   詰まることが多い。キューはテナントで均すので、1 部門が詰まっても
   ほかは進むが、**ワーカ全体が埋まると全部遅くなる**。

3. **ワーカを増やす。**

   ```sh
   kubectl -n kotonoha scale deploy/kotonoha-ingest --replicas=8
   ```

   **外部 API のレート制限に当たるので 8 が上限。** それ以上増やしても
   429 が返って再試行が増えるだけ。

4. 落ち着いたら 4 に戻す。

## 失敗した文書の入れ直し

ジョブの明細に失敗が残る。

```sh
curl -s "$BASE/v1/jobs/$JOB" -H "Authorization: Bearer $KEY" | jq '.failures'
```

`external_id` が分かるので、その文書だけ投げ直してもらう。
**1 件の失敗でジョブ全体は止めていない**ので、ほかは入っている。

## 飛ばされた文書

`skip_reason` で理由が分かる。

| 理由 | 意味 | 対応 |
| --- | --- | --- |
| `same_hash` | 本文が同じ | 正常。何もしない |
| `metadata_changed` | 本文は同じでメタデータだけ違う | 正常。メタデータは更新済み |
| `empty` | 中身が無い | 元の文書を確認してもらう |

## 対応していない形式

対応は text / markdown / html / pdf / csv。それ以外は失敗として残る。
**黙って飛ばさない**ので、明細を見れば分かる。

## ★ 既知の穴: 画像だけの PDF

**スキャンした紙の PDF は取り込めない。** テキスト層が無いので文字が
起こせない。OCR を入れていない。

- 結果は `skipped` になり、`notes.image_only` が真になる
- 品質保証部の 2018 年より前の不具合報告がこれにあたる（約 3,400 件）。
  **取り込めないまま残っている**
- OCR を入れる話は 2026/03 に出たが、費用と精度の検討をしていない

利用部門から「入れたはずのものが検索に出ない」と言われたら、まずこれを疑う。
