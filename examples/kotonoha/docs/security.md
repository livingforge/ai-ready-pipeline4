# セキュリティの決めごと

情報セキュリティ部の点検（2026/03 実施）への回答をもとにまとめたもの。
点検表そのものは `資料/情報セキュリティ点検表.xlsx`。

## 機密区分

社内の情報区分規程に従う。

| 区分 | 名称 | 外部 API への送出 | 保持期間 |
| --- | --- | --- | --- |
| 10 | 一般 | 可 | 無期限 |
| 20 | 社外秘 | 可（契約による） | 5 年 |
| 30 | 極秘 | **不可** | 3 年 |

## 指摘と回答

### 指摘 1: 極秘を外部サービスへ送出しないこと

**回答: 経路の判断を 1 か所に集約した。**

- `embed/router.py` を通らずに提供元を呼ぶ道は無い
- 判定（`tenant/classification.py`）と振り分けを分けてある
- 二重に確かめる（モデルを決めるとき／提供元を返すとき）
- 極秘のコレクションは `voyage-4-nano`（社内 GPU）に固定される
- 監査ログに経路を残す。`v_audit_violation` が常に 0 件であること

**リランクも極秘には掛けない**（提供元が外部 API しかないため）。

### 指摘 2: 検索語・文書本文をログに残さないこと

**回答: 監査ログの表に本文の列を持たない。** 検索語は SHA-256 の
ハッシュだけを残す。

> ★ **この指摘は守られていない。**
>
> `common/audit.py` の `record` が DEBUG レベルでクエリ本文をアプリログへ
> 出している。2026/05 に取り込みの不具合を追うために足したもので、
> そのままになっている。
>
> 本番の `log_level` は INFO なので普段は出ないが、障害調査で DEBUG へ
> 落とすと出る。**直す必要がある（未対応）。**

### 指摘 3: テナント間でデータが混ざらないこと

**回答: 論理分離。ただし要素ごとに分ける**（ADR-004）。

- 他テナントのものを指したら **404**（403 ではない。存在を探れないため）
- 停止中のテナントは **401**（同じ理由）
- 原文は機密区分ごとに別バケット。極秘は別の鍵で暗号化
- 埋め込みキャッシュは鍵にモデル名が入るので結果として区分ごとに分かれる

### 指摘 4: API キーを平文で保持しないこと

**回答: SHA-256 のハッシュだけを持つ。** 平文は発行時に一度だけ返す。
照合は定数時間の比較（`hmac.compare_digest`）。

失効させても行は残す（監査ログから辿れるように）。

### 指摘 5: 監査ログを 5 年保持すること

**回答: `t_audit_log` に残す。** 保持期間は設定
（`audit_retention_years = 5`）。日次のバッチが期限を過ぎたものを消す。
