# 現在の状態（2026-09-20）

監査対応として、標準 ZIP にビルド元の `source/`（テスト・検体・生成コードを含む）と `audit/`（ハッシュ、来歴、実施したテストのログ）を同梱します。パッケージ作成はそのソースコピーからビルド・テストします。依存クレートを同梱するオフライン再ビルド用 ZIP は `build/package_offline.ps1` で別途作成します。開発ツールの配布とバイト単位の再現可能ビルドは対象外です。[監査・再検証手順](audit-testing.md)を参照してください。

4.0.0-alpha.3 では Python 版の本体・配布・専用テストを削除し、Rust と PowerShell のみでビルド・検証します。削除前のソースは 7f0b9e7、配布物は arp4-publish の a286d10 に保存しています。現行の対応範囲は [利用ガイド](rust-preview.md) を参照してください。以下は移行開始時の計画と経緯です。高度な書き戻し等は今後の課題であり、現在の提供機能ではありません。

# Rust版への移行と最初のリリース

2026-09-20に合意した方針。これは実装・配布の計画であり、Rust版の提供開始を示すものではない。

## リリース目標

Windowsの空の環境でZIPを展開し、Pythonなしでスキル導入からExcelの取り込み・差分確認・書き戻しまで完了できる。

最初の対象はWindows x64とする。対応するWindowsのバージョンは受入試験で確認して公開する。
利用者にはPython、Rust、Cargo、コンパイラー、Gitの導入を求めない。
Gitでの文書管理は推奨するが、基本操作の実行条件にはしない。
Agentによる成形を試験する環境には、対象Agentとその利用に必要な設定を用意する。
ZIP展開後のCLI操作とスキル導入はオフラインで実行できるものとし、Agentサービスの通信とは区別する。

| 環境 | 最初の受入範囲 |
| --- | --- |
| Microsoft Excel未導入 | スキル導入、Excel取り込み、YAML検証、記録、差分、採用、レビュー、通常セルの書き戻し |
| Microsoft Excel導入済み | 上記に加え、行追加削除・数式・図形・画像など、現行COMエンジン相当の高度な書き戻し |

利用できない機能は理由を表示する。未対応操作を無視して成功を返さない。
現行版の全機能移植の進捗と、最初の配布物で保証する機能を区別して報告する。

## 配布

一般利用者はGitHub Releasesのビルド済みZIPを使う。ソースからのビルドは開発者向けの選択肢とする。
GitHubの「Download ZIP」はソースコードなので、READMEではReleasesの配布物へ直接案内する。

配布名は `arp4-v<version>-windows-x64.zip` とし、次を含める。

- `arp4.exe`
- 実行に必要な再配布可能な外部ライブラリ
- 本体と同じ版のClaude・GitHub向けスキル
- 導入手順、対応環境、機能別の前提条件
- ライセンスと第三者ライセンス表示

ReleasesにはZIPのSHA-256チェックサムと変更履歴も添付する。
PDFiumなどのネイティブ依存は同梱・リンク方法とライセンス条件を確認する。
利用者に追加準備を求めないことを優先し、実行ファイル一つへの集約は必須としない。

本体はプロジェクト外への配置を基本とし、利用先には文書・設定・スキルを配置する。
プロジェクトが要求する本体・スキルの版を記録し、不一致を診断できるようにする。
利用者が編集した既存スキルを保護する現行の導入規則を維持する。
更新は明示操作とし、文書操作中に自動更新しない。

GitHub Actionsでビルド・試験・ZIP作成を行う。開発中はActions成果物として検証する。
正式Releasesへの公開は、後述の受入条件を満たしたバージョンを対象とする。
MSI、パッケージマネージャー、他OS・ARM64対応、GUIは後続とする。

## 移植の構成

Cargo workspaceを用い、文書モデル・検証・出典・状態遷移の中核、形式別の抽出、
Excel書き戻し、CLI・導入処理の責務を分ける。具体的なcrate分割は依存関係を確認して決定する。

YAML正本と `.arp/` の管理データを維持する。現行Python版のデータ形式とCLIを互換性の基準にする。
互換性を変更する場合は形式の版と明示的な移行手順を設ける。
Python版は比較対象として保持し、Rust版の利用者実行時にPythonへ委譲しない。

通常セル更新は既存のZIP/XML編集方式を基準とし、変更対象以外の部品を保持する。
高度な更新はWindowsのExcel連携を独立させる。Rust化によってExcel依存が消えるとは扱わない。
PDF・OCRは外部依存、対応環境、利用不可時の診断を明示する。
意味の整理はAgent、対応表の生成・検証と書き戻しの可否判定はコードが担当する現行の責務を維持する。

## 実装順序

1. Rust/CargoとWindowsのビルド環境を整備し、ツールチェーンと依存を固定する。
2. 現行版の代表入力・出力・拒否条件を保存し、両実装を同じ入力で比較する試験を用意する。
3. Excelの保持付き更新、Excel COM、PDF・OCRの小さな試作で依存と配布上の難所を確認する。
4. 文書モデル、検証、状態確認、差分、レビューなどの中核を移植する。
5. 抽出・書き戻し・仕様整理と生成を順に移植し、現行版との比較を追加する。
6. Python不要のスキル導入と環境診断を実装し、Windows向けZIPを作る。
7. 空のWindows環境とExcel導入済み環境で受入試験を行い、記録とともに公開する。

`arp4 init` と `arp4 doctor` は新設コマンドの案であり、現在のCLIには存在しない。
実装後に利用者向け手順とスキルを同じ版へ更新する。

## 受入条件

- Python・Rust・ビルドツールを持たないWindows環境でZIPを展開して起動できる。
  開発ツールが導入済みのCIでの成功だけを、この条件の証明には使わない。
- ネットワークを無効にしてCLI起動・スキル導入・基本操作を確認する。
- 日本語・空白を含むパスと一般ユーザー権限で動作する。
- スキルの新規導入、未編集ファイルの更新、利用者による編集の保護を確認する。
- 対象Agentの新しいセッションでスキルが利用できることを確認する。
- 取り込みから成形、検証、記録、差分、採用、編集、再レビュー、書き戻しまで一巡する。
  自動試験用の成形データと、実際のAgentで確認した結果を区別する。
- 書き戻したExcelを独立した読み取り処理で再読込し、意図したセル値・型と変更対象外の保持を確認する。
- 未レビュー、古い原本、競合、未解決の対応、既存出力への上書きを拒否し、既存データを保つ。
- YAMLの型解釈、JSONの正規化、ハッシュ、改行、日本語パスの差でレビューや出典を誤判定しない。
- 高度な書き戻しは実Excelで保存・再読込を確認する。スキップや代替実装の成功を実機確認に数えない。
- ZIPの内容、依存、対応環境、試験結果、既知の制限を記録する。

失敗時の保存状態と境界条件は [テスト戦略](test-strategy.md) に従う。
実行結果は [確認記録](verification.md) に追加し、未実行の項目を成功扱いにしない。
