# 用語集

社内で使われている呼び方を集めたもの。**正準名はこの表の左端**とするが、
文書によって揃っていない。揃えきれていないのは、各部門が既に自分たちの
呼び方で運用を回しているためで、無理に統一するとかえって話が通じなくなる。

| 正準名 | 揺れている呼び方 | 主に使っている部門 |
| --- | --- | --- |
| Kotonoha | エンベディング基盤／ベクトル検索基盤／AI検索基盤 | 稟議書は「エンベディング基盤」、運用は「Kotonoha」 |
| テナント | 利用部門／契約者 | 利用申請台帳は「利用部門」、コードは「テナント」 |
| コレクション | インデックス／索引 | API は「コレクション」、OpenSearch まわりの手順は「インデックス」 |
| チャンク | 断片／分割単位 | コードは「チャンク」、キャパシティ試算は「分割単位」 |
| 取り込み | インジェスト／登録 | API は「取り込み」、CS 部門は「登録」 |
| 機密区分 | 機密度／セキュリティ区分 | 情報区分規程は「機密区分」、点検表は「セキュリティ区分」 |
| 埋め込み | ベクトル化／エンベディング | 混在。動詞は「埋め込む」で揃えたい |
| 再インデックス | 再構築／作り直し | runbook は「再インデックス」 |
| リランク | 並べ直し／再ランキング | |

## 用語の定義

**Kotonoha**
: 社内の各部門へ、文書の取り込み・エンベディング生成・検索を API で提供する
  基盤。デジタル基盤本部 AI基盤グループが内製で運用している。

**テナント**
: 利用申請を出して承認された部門の単位。機密区分・月間上限・原価センタを持つ。
  テナントをまたいでデータを見ることはできない。

**コレクション**
: 検索の単位。テナントの下に複数作れる。機密区分をテナントから継承し、
  埋め込みモデルは作成時に固定される。

**チャンク**
: 文書を検索しやすい大きさに切ったもの。埋め込みとチャージバックの単位。
  分割の規則は実装（`ingest/chunker.py`）にある。

**機密区分**
: 社内の情報区分規程に沿った 3 段階（10 一般 / 20 社外秘 / 30 極秘）。
  30 は外部 API へ送出してはならない。

**ハイブリッド検索**
: ベクトル検索と全文検索（BM25）の両方を引き、順位を融合する方式。
  型番や品番はベクトルでは当たらないので、全文の経路が要る。

**RRF**
: Reciprocal Rank Fusion。点数ではなく順位だけを使って融合する方法。
  正規化の仕方を決めずに済むのが利点。

**再インデックス**
: 埋め込みモデルを変えるときに、全チャンクのベクトルを計算し直すこと。
  旧を読ませたまま新を作り、別名の張り替えで切り替える。

## 使わない語

| 使わない | 理由 |
| --- | --- |
| RAG基盤 | Kotonoha は検索まで。回答生成は各部門が行う（※ この線引きは合意できていない。`docs/meeting/2026-05-20-cs-scope.md` を参照） |
| ドキュメント | 「文書」で揃える。API のフィールド名だけ `document` |
| AI | 具体的に「エンベディング」「検索」と書く |
