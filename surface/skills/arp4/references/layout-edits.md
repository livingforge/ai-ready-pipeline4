# 行・列の追加・削除と操作の取り消し

本文YAML・`mappings.yml` を手で編集せず、専用コマンドで行・列を変える。Excelの書式・シート・セル範囲・図形は [Excelの書式・シート・セルの操作](excel-edits.md)、PowerPointのスライドと図形は [PowerPointのスライドと図形の操作](slide-edits.md)、値は [値・数式・フォントの編集](value-edits.md)。

- Excel・Word・PowerPointの行（Word・PowerPointは表の外の段落と表の行。PowerPointの新しい段落は書式元の段落と同じ図形に入る）とExcelの列の追加削除は `mappings.yml` と本文YAMLを手で編集せず、`documents rows insert|delete|move` / `documents columns insert|delete|move` で行う（候補は `--proposal <文書ID>`、採用後は文書ID）。`--sheet <シート>` と `--reason <理由>` は必須で、`--sheet` はExcelのシート名、Wordは `document` などのパーツ名、PowerPointは `slide-N`・`notes-N` または追加したスライドの操作ID。1回の実行で操作をreason付きで記録し、追加分の値と原本への対応を保存し、削除した行・列の値を本文から除く。checkと同じ検証に通らなければ何も書き込まず、成功時は応答の `check` に結果を返す。
  - 位置は `--after` / `--before` に、原本シートの行番号（`15`・`r15`）か列名（`C`）、先に挿入した行・列のキー（`<操作ID>-<番号>`）、または `last`（値のある最後の行・列）で指定する。値のない結合の内側（右に広がる備考欄など）や図形の横など、シートが使う範囲の中なら値のある最後の行・列より後ろも指定できる。削除は `--from` に原本の行・列を指定する。
  - 値は `--values <YAML/JSONファイル>`（`-` で標準入力）に1行（列）1オブジェクトのリストで書く。行は列名がキー（`- {B: "8", C: 2025/11/21}`）、列は `r<行番号>` がキー。`--count` を省くと項目数になる。行の値は同じ列の既存値（`--style-from` の行、空ならその上で最も近い値）の型に揃う（文字列の列の数値は文字列に、日付の列の `YYYY/MM/DD` は日付に）。揃えられない値は拒否される。変換は応答の `converted` で確認する。先頭のゼロなど、表記を保つ値は引用符で囲む。
  - 書式は既定で挿入位置の上の行から罫線も含めてそのまま写す（表の最後の記録の後に足した行も罫線を持つ）。見出しの直下に挿入するときは `--style-from <データ行>` を指定する。列の挿入とセルの右へのずらしは、Excelと同じく左のセルの書式のうち左右のセルが同じ線を引く罫線だけを残す（見出しや表の右に入れた列に罫線ははみ出さない。表の右端に足した列に罫線が要るときは `documents format --from` で揃える）。
  - 結合で組んだExcelの様式（設計書の表、改訂履歴、区分を縦結合した表）に行を足すときは `--merges` を付け、書式元の行の内側にある結合を追加行にも作る（Excelの「コピーしたセルの挿入」と同じ。付けなければExcelの行挿入と同じく結合は作らず、新しい行は1列幅で折り返す。書式元の行に結合があるのに付けなかった場合は応答の `merges_not_copied` に作らなかった結合が示されるので、`documents operations remove` で取り消して `--merges` を付けて入れ直す）。2行で1組の様式は `--style-from 9:10` のように書式元の行を範囲で指定すると、追加行が組ごとにその行の書式と結合を順に写す（行数は組の倍数。`--values` の値の型も対応する書式元の行に揃う）。書式元の行のセル単位の書式（斜線・塗り）も写るので、出力を描画して確認する。結合の中への挿入で写す結合が既存の結合と重なる場合は拒否される。
  - 先に `--dry-run` で `operation`・`span`・`neighbors`（挿入・削除位置の上下の行）・`converted` を確認する。`--id <操作ID>` を付ければ同じコマンドの再実行は `unchanged` になり、二重には挿入されない。
  - 他の担当と並行する場合は `documents check <文書ID> --include-hashes` の `content` を `--base` に渡す。その後に文書が変わっていれば `base_changed` で拒否される。
  - 拒否は `error.code` で判断する。`sheet_not_found`（`error.sheets` にシート一覧）、`invalid_position`、`count_mismatch`、`invalid_values`、`value_type_mismatch`、`operation_id_conflict`、`merged_non_anchor`（挿入で広がる結合の左上以外への値。結合の左上に書くか、結合の外に挿入する）、`category_row_deleted`（本文の区分の値を持つ行だけを、区分の他の記録を残して削除しようとした。Excelで区分を残る行へ書き直して再importするか、区分の行をすべて削除する）、`structural_edit_unsupported`（マクロシート・ActiveXコントロール等を含むブック、テーブル見出しの切断など。Excelで編集して再importする）、`vba_not_updated`（VBAプロジェクトを持つブック。[対応形式](formats.md) にある利用者の了承を得て `--vba-unchanged` で再実行する）、`invalid_arguments`（VBAプロジェクトのない文書への `--vba-unchanged` 等）、`invalid_document`（編集前の文書がcheckに通らない）、`unsupported_format`、`source_changed`、`invalid_count`、`invalid_reason`、`invalid_operation_id`、`validation_failed`。
  - 記録した操作は `documents operations list <文書ID>` で確認し、`documents operations remove <文書ID> --id <操作ID> [--dry-run]` で取り消す（候補は `--proposal`）。挿入した行・列・スライドの値は本文から除かれ（その値への `documents values` の記録も除かれる）、挿入したセルの値は除かれてずらしたセルが元の位置に戻り、削除した行・列・スライド・セルの値は原本の値で戻り、削除前の `documents values` の編集が当て直される（`reapplied_edits`）。後の操作が依存する操作（同じシートの後の行・列・セル・画像の操作、その操作が追加したスライド・図形を指す操作）は `operation_has_dependents`（`error.dependents`）で拒否されるので、後の操作から取り消す。
