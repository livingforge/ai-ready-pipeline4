# 本文の読み方と検索

採用データの本文（表・図形・画像）の読み方、設計情報の検索、人が確認するページ（view）の作成。

- Excel本文の画像・グラフ・図形は `image: null`・`chart: null`・`drawing: null` として表す。線でつながった図形は1つの `diagram`（`shapes` に図形の種類・位置・文字、`lines` に「A → B」形式の線）にまとまる。線の端は原本の接続先、記録がなければ近接で推定した図形・セルで、推定した端は括弧で注記されるため、近接の推定は原本の画像で確かめる。チェックボックスは1つの `checkbox`（`text` にラベル、`checked` に原本の状態、`linked_cell` にリンク先セル、`at` に位置）になり、ラベルと状態を本文の並び順で突き合わせる必要はない。`documents elements-read <文書ID> --out <プロジェクト>/.arp/cache/elements/<新規名>.json`（候補は `--proposal`。`.json` は表の外の要素と表のセルを1行ずつ書くので、`.yml` より少ない行数で読める）の出力で、同じ配列位置の `element_metadata` が持つ `ref` を同じページの `visuals` で解決する。画像はasset、グラフはchart_part、原本オブジェクトはsourceから確認し、解釈はstructure-readのvisualsをsourceで照合する。図形文字のメタデータの `visual` はその参照との対応であり、OCRや画像説明を原本文字へ混ぜない。セルアンカーのない図形は本文末尾に置かれるため、本文順だけで位置や意味上の読み順を断定しない。
- すべての対応文書の本文は読む順の文書要素として読む。本文の表は `columns`（先頭の見出しの記録の値）と `rows`（見出し以外の記録の木）で表す。構造解釈がその表だけに結び付けた文字は、その前の `title`（表の上の表題）と `notes`（単位・右隣の行の注記・直下の注記のリスト）に入る。複数の表にかかる共通の表題は表の前の `text` のまま。ノードは1記録で、列の見出しの文字（見出しのない列は列名、同じ記録で見出しが重なる列は `見出し(列名)`）をキーに値を持ち、見出しを持たないツリー記号などのセルを `marks`、その記録の名前が見出しとなる記録を `children` に持つ。同じ列で下へ複写した数式が3ノード以上続くときは、先頭のノードだけが数式を持ち、`fill_down` に列のキーと先頭を含めて続くノードの数を書く。続く同じ並びのノードはそのキーを省き、先頭の数式の相対参照をノード1つごとに1行下へずらした数式を持つ（省いたキーを空欄と読まない）。何も書かないノードが2つ以上続くと、`blank_records` だけを持つノードがその数の空のノードを表す（その記録の数式は上の `fill_down` から読む）。縦に結合するか先頭の記録の行だけに書いて複数の記録の見出しとなる区分は、記録とは別のノードで、区分の値を同じ規則のキーで持ち、範囲の記録を `children` に持つ（区分の値は先頭の記録のノードには置かない）。ID・役割・見出し関係・結合・数式区分は `documents elements-read` の出力の同じ要素位置の `element_metadata` で読む（記録の並びは本文の木を上から順にたどった順）。`layout.yml` を直接読まない（フォントは番号で、書き戻し先はIDから決まる）。原本照合には位置対応と `documents extraction-read <文書ID> --out <プロジェクト>/.arp/cache/extraction/<新規名>.json`（候補は `--proposal`）の出力を使う。`extraction.json` はフォント・書式を番号で持つため直接読まない。書き戻し対応形式では本文の値を `documents values` で変える（`element` に `element_metadata` の要素IDを指定できる）。本文YAMLとメタデータは直接編集しない。要素・ノード・marksの追加削除・並べ替え、キーの変更、木の組み替え（記録を別の区分へ移すことを含む）はvaluesでも行わない。表と本文の区分は `documents structure-save`、行列の追加削除と行・列の移動は専用コマンドを使う。構造保存は本文と位置対応も更新するため、未適用の行列操作があれば先に適用する。
- 設計情報は `documents search "検索語"` で探す。索引がない、またはファイルが増減・サイズか更新日時が変わっていれば検索が先に索引を更新するので、事前の更新は不要（応答の `summary.source_checked_this_search` が更新の有無）。サイズと更新日時を保ったまま原本が書き換えられた疑いがあるときだけ `documents search-refresh` で全バイトを照合する。採用済み抽出の段落・表の行を検索し、原本位置・抽出結果へのポインター・索引更新時点の原本とレビューの状態を返す。文書ごとの情報（`document_id`・原本パス `source_path`・`state`・`structure_reviewed`）は応答の `documents` に短い参照（`d1` など）をキーとして1回だけ載り、各ヒットは `document`（表の行は `table_ref` の表の `document`）の参照でそれを引く。`state` は `reviewed` と正常でない項目だけを持つ（`source_current: false`・`source_missing: true`・`content_differs_from_extraction: true`。載っていなければ原本は現在のもので未反映の編集もない）。表以外のヒットの `title` はシート・ページ名とその箇所にかかる見出しで、`sources[]` は `sheet` と `address`（行位置のある原本では `position` も）で原本の位置を示す。セルのない図形の文字は `address` の代わりに抽出結果への `pointer` を持つ。`--document <文書IDまたはフォルダ>` で絞り、続きは同じ条件で `--offset <page.next_offset> --revision <revision>`。`omitted_fields` があれば絞り込みと `--full` で本文・出典を確認する。構造解釈のある表の行は `values` に全セルを列順で返し（長い行は断片に分かれ、各断片のセルだけを返す）、表（文書の参照 `document`・列名のリスト `columns`・同じ順の列見出しのリスト `column_headers`、入れ子なら親の `headings`・`within`）は応答の `tables` に1回だけ載り、各ヒットは `table_ref` で参照する。値は同じ位置の `columns` の列名・`column_headers` の見出しと組で読む（`column_headers` がなければその表に列見出しはない）。`null` の値は `unread` の状態を確認する。`heading_only` 付きのヒットは本文ではなく見出しだけに一致したもので、本文一致の後に見出しの群ごとに並ぶ（`group_hits` は群の件数）。`failed` があれば不完全な検索結果であり「該当なし」と扱わない。赤字など書式で探すときは `--color`（`RRGGBB`・`red` などの系統・`accent1` などのテーマ色枠・`auto`）・`--font`・`--size`（`14..` など）・`--bold`・`--italic`・`--underline`・`--strike`・`--highlight`・`--fill`（塗りつぶしのあるセル）で絞る。検索語を省くと書式だけで探す。書式・強調はセルの文字の一部だけに付いていても一致し、複数の条件は同じ文字で満たす必要がある。各ヒットの `formatted` が書式に一致した文字を持つセル（`address`。図形の文字は `pointer` だけ）と、一致した部分ごとの位置（`start`・`end`）・文字（`text`）・書式の全体（`format`）。使われている色・フォントは先に `documents search-formats` で確認する。検索順位を仕様の承認とみなさない。索引はローカルキャッシュで、用語辞書は `.arp/search-synonyms.yml`。詳細は docs/guides/document-search.md。
- 人が原本の見た目で本文を確認するページ（view）は `documents view <文書ID>...` で作る。文書IDは空白区切りで複数並べられ、フォルダIDはその配下の全文書、`--all` は全文書が対象。1回のコマンドにまとめ、文書ごとに実行し直さない。オプションは `--all` と `--proposal` だけで、出力先は指定できない（`--out`・`--document` はない）。原本のパス（`docs/設計/a.xlsx`、絶対パス、`\` 区切り）もそのまま文書として受け付けるので、IDへの変換や事前のstatus確認は不要。採用済みの文書は採用データを、未採用の文書は候補を描く（応答の `proposal: true`）。`--proposal` は採用済み文書の候補を見るときだけ付ける（`pending_proposal: true` は、描いたのが採用データで、別に候補があることを示す）。応答の `views[]` が文書ごとの `view`（`.arp/view/<文書ID>.html`、候補は `.arp/view/proposal/<文書ID>.html`）・`pages`・`differences`（本文が原本から変えた値・フォントの数）で、`summary` が件数（文書が多く `omitted_fields` に `views` が入っても全件作成済み）。`failed[]` があると終了コード2になるが、他の文書のページは作成済み。`reason` に従って該当文書だけを直し、その文書だけで再実行する（未取り込み・取り込み後に原本が変わった文書は `reason` が示す `documents import` を先に実行する。似た名前の文書IDが示されたらそのIDを使う）。ページは追跡対象外の生成物で、本文・管理データ・原本を変更しないので、record・adopt・reviewをやり直す必要はない。利用者には `view` のパスを伝える。
